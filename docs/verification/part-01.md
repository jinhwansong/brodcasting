# 1단계 제작 검증

이 기록은 교재 제작자의 실행 결과입니다. 학습자의 제출·설명·독립 변경 완료를 뜻하지 않습니다. 검증 대상은 목록·상세·공유 상태·disclosure·포커스·타이머 정리 실습입니다. 실제 영상·서버 기능은 없습니다.

## 환경과 실행 결과

Node.js 24.19.0, npm 11.9.0. React/ReactDOM 19.3.1, TypeScript 7.0.2, Vite 8.3.4, React plugin 6.1.2, Vitest 5.0.5, jsdom 30.1.3, Testing Library React 16.3.3 / user-event 14.6.8. 루트와 독립 완성본 lockfile을 사용했습니다. 새로운 라이브러리는 추가하지 않았습니다.

| --- | --- |
| 루트 `npm ci` | exit 0 |
| `npm run typecheck:part-01` | exit 0 |
| `npm run build:part-01` | exit 0 |

시작 코드의 실패는 미구현 과제의 증거이며 빌드 실패가 아닙니다. JSON reporter로 최종 개수를 확인했고 모듈 오류나 timeout을 의도된 실패에 포함하지 않았습니다. 호스트의 기존 npm `Unknown env config "http-proxy"` 경고는 출력되지만 명령들은 위 결과로 종료했습니다.

## RED → GREEN

1. Task 1: 선택 함수·상세·공유 즐겨찾기·닫기 포커스 검증을 먼저 작성했습니다. 미완성 시작 코드에서 9개 중 7개 실패, 2개 통과를 확인했습니다. 재로딩 테스트는 선택 화면이 실제 열린 것을 먼저 확인하도록 강화해 거짓 성공을 막았습니다.
2. Task 2: 펼침 영역 6개와 타이머 5개를 추가했습니다. 시작 코드 20개 중 17개 실패, 3개 통과였습니다. StrictMode와 전환·닫기·언마운트 수명도 포함합니다.
3. Task 3: App의 실제 선택과 타이머 연결 검증을 먼저 추가했습니다. 완성본 작성 전 21개 중 18개 실패, 3개 통과. 같은 계약으로 구현한 뒤 21/21 통과했습니다.

통합 검증 초기에 fake timers와 비동기 userEvent 클릭이 함께 대기해 timeout이 발생했습니다. 임시 loaded/selected 표시로 첫 클릭 대기에 갇힘을 확인했습니다. 타이머 연결 검증에만 동기 fireEvent를 쓰고 닫기 후 0ms 대기 작업을 비운 뒤 남은 타이머를 검사했습니다. 시간 증가·전환 초기화·닫기·언마운트 assertion은 유지했습니다. 선택·키보드·포커스 검증은 실제 시간 userEvent를 사용합니다. 수정한 검증으로 시작 코드의 실패가 timeout이 아닌 assertion임을 다시 확인했습니다.

## 독립 설치·제공

새 임시 디렉터리에 완성본의 src·package.json·package-lock.json·index.html·tsconfig·Vite 설정만 복사했습니다. 기존 node_modules·dist 없이 `npm ci`, `npm run typecheck`, `npm run build` 모두 exit 0입니다. 같은 검증 프로세스에서 로컬 Vite를 시작해 `/`와 `/src/App.tsx`의 HTTP 200 및 응답 본문을 확인하고 종료했습니다. 별도 실행 세션 사이의 최초 HTTP 접근은 연결 거부였으며, 최종 성공 증거는 서버와 요청을 같은 프로세스에서 수행한 재검증입니다.

이것은 HTTP 제공 확인입니다. 실제 브라우저 렌더링·Tab 이동·390px/1280px 가로 넘침·스크린리더 검증은 **사용자 요청으로 미실행**입니다. 브라우저 설치를 재시도하지 않았습니다. [후속 목록](../tasks/part-01/browser-checklist.md)은 모두 미체크입니다.

## 구조와 판단 기록

- App에 공유 query·favorites·선택 id를 두고 표시 목록과 선택 객체를 파생합니다. 필터로 숨겨도 상세를 유지하고, 재로딩 조작은 선택을 해제합니다.
- 목록 옵션은 일반 disclosure입니다. Escape는 트리거로, 바깥 클릭은 클릭한 요소로 포커스를 유지합니다. 문서 이벤트는 열려 있는 동안만 등록하고 같은 함수를 제거합니다.
- 상세 제목은 선택 id 변경 때만 포커스를 받습니다. 즐겨찾기 변경은 포커스를 빼앗지 않습니다. 닫기 시 연결된 원래 버튼 또는 검색 입력을 사용합니다.
- 타이머는 장난감 체류 카운터입니다. 영상 시간·정확한 시청 통계·백그라운드 보정 기능을 주장하지 않습니다.
- Ruling: 빌드 가능한 Task 1을 위해 CSS 골격을 Task 3보다 먼저 제공했습니다. 잘못 판단했을 때 비용은 기능 없는 파일의 작업 순서 변경입니다.
- Ruling: 계획의 Hook 검증 외에 App 타이머 연결 검증을 추가했습니다. 잘못 판단했을 때 비용은 중복 검증 1개이며, Hook만 정답이고 App이 연결되지 않은 결함을 잡습니다.
- Ruling: focus trap이나 복잡한 ARIA menu 대신 일반 disclosure/group과 바깥 pointerdown을 사용했습니다. 승인된 조작 계약을 따릅니다. 잘못 판단했을 때 추가 메뉴 탐색 계약의 설계가 필요합니다.
- 루트 실행 기본값과 학습 단계 0·미시작을 유지했습니다. 1단계는 명시적 명령으로만 실행합니다. 참고 완성본은 workspace에서 제외하고 별도 lockfile로 설치합니다.
- Ruling: 사용자의 강의별 main 푸시 지시와 이후 중간 승인 생략 위임에 따라 통합 방식은 이미 결정됐습니다. 최신 main을 다시 확인하고 expected SHA 조건으로 게시합니다. 잘못 판단했을 때 비용은 완성된 강의가 공유 브랜치에 예상보다 먼저 반영되는 것이며 되돌림 커밋으로 복구합니다.

## 독립 리뷰

새 컨텍스트 리뷰 1회: `5541e92..aca4b2c`의 전체 변경을 독립 검토했습니다. 중요한 문제 1개와 경미한 문제 1개를 확인했습니다.

- **Important / 수정:** 문서 리스너 정리를 지워도 기존 펼침 영역 검증 6개가 통과했습니다. 학습자가 정리 과제를 빼먹어도 통과하므로 중요한 검증 결함으로 판단했습니다. 닫힌 상태에서 바깥 요소에 포커스를 두고 Escape를 다시 누르는 검증을 강화하고, 실제 DOM 등록은 유지하면서 type·함수·capture의 등록/해제 짝을 추적하는 검증 1개를 추가했습니다. 호출 순서나 정확한 등록 횟수는 고정하지 않습니다. 완성본의 두 removeEventListener를 임시 제거한 재현에서 7개 중 **2개 실패 / 5개 통과**를 확인하고 원래 정리를 복구했습니다. 최종 1단계 **22/22**, 0단계 **24/24**, 도구 호환성 **3/3** 통과입니다. 시작 코드도 **19개 assertion 실패 / 3개 통과**로 다시 확인했습니다.
- **Minor / 보류:** `checks/part-01/run.mjs`가 내부 인자로 browser를 허용하지만 해당 Playwright 설정은 없습니다. 루트의 1단계 명령·교재에는 그 모드를 안내하지 않습니다. 실제 브라우저 검증을 추가하는 후속 작업에서 runner의 지원 모드도 정리합니다. 현재 실행은 unit 명령만 사용합니다.
- **Declined to judge / 판단:** 실제 렌더링·넘침·네이티브 Tab 이동·스크린리더는 리뷰도 검증하지 않았습니다. 사용자 요청에 따른 후속 검증으로 유지합니다. 잘못 판단했을 때 비용은 실제 환경의 시각·접근성 결함이 뒤늦게 발견되는 것입니다.

리뷰가 만든 임시 JSON 보고서는 게시 대상에서 제거했습니다. CURRICULUM.md 원문과 기존 0단계 구현·과제는 보존했고, 기존 authoring-only Node 정책 검사에 새 완성본만 추가했습니다. 문서 링크·비밀값 패턴·diff 공백도 확인했습니다.
