# 디자인 시스템 제작·검증

기준일: 2026-10-21. 사용자의 ‘UI를 중요하게 보고 디자인 시스템부터 만들기’ 요청에 따라 [설계](../superpowers/specs/2026-10-21-onair-design-system.md)와 [실행 계획](../superpowers/plans/2026-10-21-onair-design-system.md)을 적용했습니다. 학습자는0·미시작입니다.

## 적용 결과

- [공통 원본](../../apps/broadcast/client/src/ui/README.md)에 의미 색·글자·간격·조작 크기·포커스와 작은 React 부품을 모았습니다. 외부 UI 패키지는 추가하지 않았습니다.
- 목록·방송 카드·팔로우·회원·채팅·공지·WebRTC의 실제 조작에 공통 부품을 적용했습니다. `#/design-system`은 같은 부품으로 만든 살아 있는 가이드입니다.
- WebRTC 독립 시작 코드와 완성본에도 제공 UI를 맞췄습니다. ICE와 방 권한의 학습 TODO 두 곳은 보존했습니다. 예전0~11단계 화면을 일괄 변경하지 않았습니다.
- 제작 중인 알림5주 UI도 같은 부품을 사용하도록 바꾸고 기존 client9검사·타입 검사를 확인했습니다. R5는 교재·독립 설치·최종 브라우저 검증이 남은 미게시 작업이며 이번 디자인 시스템 완료와 구분합니다.
- [쉬운 설명과 직접 해볼 실습](../../apps/broadcast/client/src/ui/README.md), [사이트 안내](../../apps/broadcast/DESIGN_SYSTEM.md)를 남겼습니다.

## 실행한 검사

Windows·Node24.15.0에서 실제 실행했습니다.

| 검사 | 관찰 결과 |

| `npm run verify:broadcast:standalone` | 저장소 밖 소스 복사·새 npm ci·타입·서버/클라이언트 빌드 통과 |
| `npm run verify:webrtc-01:standalone` | 독립 교재 복사·새 npm ci·타입·빌드·단위19·실제 DB/HTTP/소켓9통과 |

| R5 미게시 회귀 | client9·클라이언트 타입 검사 통과 |

부품 검사는 미구현 상태에서6실패 후 구현하여 통과했습니다. 실제 브라우저에서 메뉴 선택 색이 지워지는 CSS 적용 순서 문제를 찾았습니다. 모든 CSS 진입점에 `reset, tokens, app, components` 순서를 먼저 선언하도록 수정했고 순서 검사도 실패→통과를 확인했습니다. 새로고침 후 실제 선택 메뉴 색 `rgb(120,225,205)`, 배경 `rgb(33,59,55)`를 확인했습니다.

본문·표면·보조 글자·주요 버튼·오류·경고의7색 쌍은 계산상4.5 이상의 대비입니다. 모든 요소/상태에 대한 접근성 인증을 뜻하지 않습니다. Vite의 기존 확장자 없는 설정 import에 대한 미래 `configLoader:native` 경고는 남아 있으며 현재 빌드는 성공했습니다. jsdom의 영상 API 미구현 안내와 실제 영상 검증은 구분합니다.

## 실제 브라우저 관찰

[관찰 JSON과 화면](../experiments/design-system/README.md)을 남겼습니다. 제작자가 소유한 loopback 일회용6단계 DB와 사이트를 사용했습니다. 사용자가 이미 승인한 `browser_learner`의 r1 참여·관리 권한만 적용했습니다.

- 데스크톱 client폭1265px, 휴대폰 override360px의 실제 client폭345px에서 가로 넘침이 없었습니다. 휴대폰의 공통 버튼은44px, 영상 표시 폭은311px였습니다.
- 가이드 팔로우와 카드가 같은 상태로 바뀌었습니다. 예제 대화상자의 Escape 종료·열기 버튼 초점 복귀, Tab 이동의 민트색2px 포커스 테두리를 확인했습니다.
- 검색 결과 없음→전체 방송 보기→6개 목록 복구, 실제 회원가입/로그인/로그아웃, 채팅 발송/공지 저장과 새로고침 후 DB 이력을 확인했습니다. 입력한 HTML 표시는 일반 글자로 보였습니다. 한글 IME 자동 입력이 중복 문구와 끝 글자를 넣었으므로 정확한 타이핑 문자열 일치를 검증했다고 세지 않습니다.
- 두 탭에서 새 송출/시청 버튼으로640×360 WebRTC 영상을 받았고 `readyState=4`였습니다. 실제 화면 통계가274→1,274프레임,360,110→1,617,059bytes로 증가했습니다. 휴대폰 표시와 종료 후 프레임/바이트0·영상 폭0도 확인했습니다. 카메라·마이크·화면 공유는 실행하지 않았습니다.
- 오류·저장 중·비활성 예제는 실제 공통 부품으로 표시했습니다. 가이드의 예제 동작은 예제라고 명시하며 서버 장애 실험이나 실제 방송 건수로 세지 않습니다.
