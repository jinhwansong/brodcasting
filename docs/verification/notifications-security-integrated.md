## 통합 사이트

- 실제 DB·Redis·HTTP·Worker18검사, UI15, 디자인 조작9/스타일4, RTC단위19/실제 DB·소켓9, 도구 정책33이 통과했습니다. 타입 검사와 빌드도 통과했습니다.
- CSP 헤더 검사1, 실제 HTTP·Socket.IO 프록시와 종료 검사1을 통과했습니다. 독립 WebRTC 복사본도 새 설치·타입·빌드·단위19/실제9를 확인했습니다.
- 최종 독립 설치에서 통합 사이트의 큐 의존성 잠금 파일 누락을 찾아 갱신했습니다. 다시 저장소 밖 npm ci·타입·server/client 빌드가 모두 exit0으로 끝났습니다. 환경 파일은 복사에서 제외했습니다.
- 실제 빌드 화면에서 Worker를 끄고 접수하면 빈 알림함이 유지되고, Worker를 다시 켜면 같은 사건이 한 번 도착했습니다. 읽음 처리 후 API 재시작·새로고침 뒤 로그인과 읽음 상태가 유지됐습니다.
- 모바일345px에서 가로 넘침 없이 알림함과 안 읽은 수를 확인했습니다. [화면 증거](../experiments/notifications-security/README.md).
- F3 정상 API·WebSocket과 320×180 테스트 영상·자막1개를 확인했고 영상은 4초 끝까지 재생됐습니다. [CSP 화면](../experiments/security-frontend/README.md).
- F2 독립 GUI를 별도로 브라우저 검증했다고 주장하지 않습니다. 같은 인증 기반을 쓰는 통합 사이트의 로그인·읽음·재시작 관찰과 F2의 독립 서버/화면 자동 검사를 구분합니다.

## 저장·보안 경계와 검토

DB 사건을 먼저 저장하고 큐에는 ID만 넣습니다. 큐 실패는 queued:false이며 성공한 알림 도착으로 표시하지 않습니다. 사용자별 생성 상한100, 목록20, 미처리 재접수 한 번50건입니다. 행 잠금과 트랜잭션으로 동일 사건 중복·순번 역전을 막고 읽음의 첫 시각을 보존합니다. 사용자 ID는 세션에서 가져옵니다.

본문은 React 텍스트로 출력하고 F1 링크는 정확한 HTTPS origin만 허용합니다. 통합 CSP는 실제 빌드 응답 헤더이며 인라인 스크립트/eval을 허용하지 않습니다. 로컬 HTTP 실습과 공개 HTTPS 운영은 구분합니다. 의존성 audit 기록의 취약점0은 해당 시점의 조회 결과이며 보안 인증이 아닙니다.

자체 검토로 소유권·CSRF·SQL 바인딩·중복 저장·큐 장애·프로세스 종료·임시 자원 정리를 확인했습니다. F3의 사용하지 않는 복사 코드를 제거하고 빌드 서버 종료 때 열린 업그레이드 소켓을 닫도록 정리했습니다.

## 한계와 별도 후속

알림은 사이트 내부 실습 알림입니다. 메일/FCM/OS 푸시가 아니며 목록·안 읽은 수는 진입/조회/읽음 처리 때 갱신합니다. 자동 실시간 푸시를 제공하지 않습니다. 공개 배포·외부 부하·BunkerWeb·기존0~11 전체 브라우저 검증·물리 PC 두 대의 카메라/마이크/LAN HTTPS는 이번 완료 범위 밖입니다. 원격 CI 결과는 실제 확인 후 별도로 기록합니다.
