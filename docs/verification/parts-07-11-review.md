## 검토 범위와 한계

## 발견해서 수정한 사항

1. 9단계 Gateway를 useValue로 바꾸니 Nest의 WebSocket 탐색에서 제외되어 실제 연결 검사가 실패했다. 원래 class provider를 유지하고 폭만 Symbol 토큰으로 주입했다. 실제 세션·회원권·방 이동·폐기·저장/복구31개 검사를 다시 통과했다.
2. 10단계 프록시까지 internal 네트워크에만 두면 이 Docker Desktop 환경에서 호스트 HTTPS 입구가 열리지 않았다. 내부 ready는 성공하고 호스트는 ECONNREFUSED였다. web만 입구 네트워크에도 연결하고 API/DB는 내부 전용으로 유지했다. HTTPS·WSS·포트 비공개·정확한 프록시 신뢰를 실제 확인했다.
3. 의도된 실패 배포에서 HTTP 오류 대신 연결 중단/제한 시간이 날 수 있었다. 검사기는 해당 고장 구간의 알려진 연결 실패만 실패 배포로 인정하고 정상 복귀는 다시 실제 준비 상태·세션·정상 이미지 ID로 확인한다. TLS 검증 오류를 성공으로 숨기지 않는다.
4. 저장소 아래 임시 복사본은 상위 node_modules를 참조할 여지가 있었다. 7·8·9·11 독립 설치를 저장소 밖 OS 임시 폴더로 옮겼다. 정리 전 realpath가 의도한 임시 폴더 안인지 확인하고, 자신이 만든 폴더만 삭제한다. 10단계는 source-only Docker context로 검증한다.
5. 9단계 발송 반복의 시간 경계에서 한 번 더 보낼 수 있어 정수 슬롯 상한을 추가했다. WebSocket 연결 수와 HTTP keepalive 수를 나누고, 성공 ack뿐 아니라 기대 수신 수·중복·해제 뒤0연결을 검증한다.
6. 10단계 검사에서 부모 터미널의 이미지 설정을 물려받지 않도록 생성한 프로젝트의 이미지 이름을 명시하고, 일회용 이미지도 같은 소유 범위에서 정리한다. 백업은 메모리에서 전달하며 비밀번호·쿠키·본문/쿼리 marker가 로그에 없는지 실제 요청으로 확인한다.

## 단순화·보안·교육 확인

- 7/8/11 화면과 6→9→10 선수 코드의 분리는 독립 실습을 위한 의도된 복제다. 원본0~6 구현을 재작성하거나 공통 프레임워크로 묶지 않았다. 불필요한 실험 변수 하나를 제거했고 새로운 운영 선택지는 추가하지 않았다.
- 보관·대기·표시·재시도·동시 전달 상한, 현재 세션/회원권, CSRF·Origin·Secure 쿠키·정확한 프록시 IP·제한 DB 역할을 유지한다. 성능을 이유로 권한 검사를 지우지 않는다.
- 새 테스트는 결과·정리·실패 경계를 검사한다. 보호한 공개 검사를 줄이거나 실패를 통과로 바꾸지 않았다. 로그 whitelist는 단위 검사와 실제 본문/쿠키/쿼리 marker로 확인한다.
- 11단계 상한 변경은 현재 글에 즉시 적용하며 생성 타이머의60초 예약을 새로 시작하지 않는다. 선택값과 방별 재생 수명이 다르다는 점을 교재에서 설명한다.
- 쉬운 lesson·파일 지도·예상→구현→확인 순서를 제공했다. 핵심 TODO와 독립 변경은 남기고 학습자의 사례·성공 주장·설명을 대신 채우지 않았다.
- 실제 브라우저·시청 지연·운영 최대 접속자 수·공개 배포·유료 자원·P2P/CDN 구축은 완료라고 주장하지 않는다. 별도 lint 명령은 저장소에 없다. 타입·빌드·공개 검사·실제 HTTP/DB/WSS/복구와 링크/도구 정책으로 확인한다.

## 판정

현재 제작 범위에서 남은 차단 항목은 없다. 실제 브라우저와 독립 리뷰는 명시한 미확인 범위다. CI·원격 게시 결과는 각 검증 문서의 게시 절에서 별도로 확인한다.
