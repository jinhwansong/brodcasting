# 2단계 — HTTP API와 느린 응답 설계

## 의도와 범위

사용자는 기존 본 과정의 다음 강의를 계속 제작·검증·커밋·푸시하도록 요청했다. F1~F3는 추가 보안 강의이며 본 과정의 끝이 아니다. 이번은 원본 CURRICULUM.md의 2단계(3주)이며 SECURITY_CURRICULUM.md의 서버 입력 과제를 함께 구현한다. 학습자는 현재 0·미시작으로 유지한다.

NestJS 메모리 API와 React 클라이언트를 독립 client/server 폴더로 제공한다. 목업만 확장하면 실제 HTTP와 서버 검증을 배울 수 없고, raw Node 서버는 원본의 NestJS 요구를 빠뜨리므로 NestJS + Vite 개발 프록시를 선택한다. 데이터베이스·인증·실제 영상은 이후 단계다.

## 구조와 계약

- labs/part-02/client는 1단계의 완료된 UI 선수 기능을 제공하고 API fetch·최신 요청 처리만 과제로 남긴다. server는 정상 기동되는 Module·Controller·Service 골격에서 조회 규칙과 DTO/Pipe를 과제로 남긴다.
- GET /api/broadcasts: 선택적 search(문자열, 최대 80), sort(viewers-desc 또는 title-asc), scenario(normal/slow/error). 반환 {items: Broadcast[]}.
- GET /api/broadcasts/:id: id는 소문자 영숫자와 하이픈 1~32자. 선택적 scenario만 받는다. 같은 Broadcast 반환, 없는 id 404.
- POST /api/search-preview: 목록과 같은 DTO를 JSON으로 받아 200 {items}를 반환하는 로컬 입력 검증 실험이다. 데이터를 저장하거나 변경하지 않는다.
- 미정의 필드·잘못된 타입·배열·null·범위 초과는 400, JSON 본문 8kb 초과는 파싱 계층에서 413. 문자열 타입 선언으로 런타임 검증을 대신하지 않는다.
- 최종 리뷰 보강: DTO 변환 전 own key를 DTO별 허용 목록과 비교하는 RawInputKeysPipe를 전역 ValidationPipe 앞에 둔다. 변환 중 제거될 수 있는 constructor·toString·prototype·hasOwnProperty·__proto__도 미정의 필드로 거부한다.
- 모든 API 응답은 Cache-Control: no-store. 캐시의 저장·재사용·재검증 개념을 설명하되 별도 결과 캐시를 도입하지 않는다.
- slow는 검색어 trim 길이 0~1이면 450ms, 2 이상이면 30ms 지연한다. error는 503. 지연은 로컬 서버의 비동기 대기이며 클라이언트 abort가 서버 작업 취소를 보장하지 않는다.
- 서버는 127.0.0.1:3002에만 기본 바인딩한다. Vite /api 개발 프록시를 통해 같은 origin으로 호출한다. 공개 배포·CORS 인증·유료 인프라는 범위 밖이다.
- 클라이언트는 목록과 상세를 각각 로딩·성공·빈 결과·404·기타 오류로 처리한다. 검색/정렬과 상세 전환에서 이전 응답·이전 실패가 새 화면을 덮지 않아야 한다. 정리 때 AbortController를 abort하고, abort를 무시한 transport에서도 이전 결과를 무시한다.
- 목록 조건이 선택 방송을 숨겨도 별도 상세 API를 통해 유지한다. 즐겨찾기는 기존 메모리 UI 상태이며 서버 저장은 3단계다.

## 제작·검증

시작 코드·공개 검증·힌트·빈 제출 양식·별도 독립 설치 완성본을 제공한다. 서버 검증은 tsc로 decorator metadata를 포함해 빌드한 Nest ESM 앱을 실제 loopback HTTP로 호출한다. Vite 변환으로 Nest metadata를 추정하지 않는다. 클라이언트는 fetch 계약과 지연 제어 Promise로 응답 역전·Abort·언마운트·실패 복구를 검증한다. 마지막에는 실제 API와 클라이언트 로더의 연결도 확인한다.

브라우저·Network 패널·실제 반응형/보조기술 검증은 사용자 요청으로 후속 미실행이다. 독립 설치·타입 검사·빌드·실제 HTTP, 기존 0/1단계 회귀, 마지막 독립 리뷰를 마친 완성된 강의만 main에 게시하고 전체 tree 일치를 확인한다. 계획 검토와 실행은 사용자의 기존 위임에 따라 중간 승인 없이 직접 진행한다.
