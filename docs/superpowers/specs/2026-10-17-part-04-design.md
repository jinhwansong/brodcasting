# 4단계 로그인과 권한 — 제작 설계

## 목적과 범위

원본 CURRICULUM.md의4단계3주 과정을 제작한다. 가입·로그인·로그아웃, 개인 즐겨찾기, 방 관리자 공지 수정을 실제 PostgreSQL·HTTP로 검증한다. 제작 완료와 학습자의 설명/독립 변경 통과를 구분하고 학습0·미시작을 보존한다. 사용자의 중간 승인 없는 계획·제작·커밋·푸시 위임에 따라 자체 검토 후 native 방식으로 실행한다. 새로운 인증 하위 시스템이므로 설계·계획을 먼저 기록한다. 브라우저 검증은 후속이다.

기존 PostgreSQL에 서버 세션을 저장하는 구성을 선택한다. JWT와 별도 인증 공급자는 이번 서버 세션 학습과 폐기 검증에 필요하지 않다. Redis·OAuth·메일 인증·비밀번호 재설정·MFA·공개 서비스 배포는 추가하지 않는다. 개발 서버를 loopback으로 제한하고 production 모드 실행은 거부한다. HTTPS·Secure 쿠키·프록시·공개 악용 방지는10단계/보안 강의에서 이어간다.

## 기술과 데이터

기존 React/Nest/TypeScript/Vite/Vitest/pg 버전을 유지한다. Node 범위는 `^22.22.2 || ^24.15.0 || >=26.0.0`. argon2 0.45.1, express-session 1.19.0, connect-pg-simple 10.0.0, csrf-sync 4.2.1, express-rate-limit 8.7.1을 정확히 고정하고 타입 패키지·lock도 기록한다. 실제 설치 API/Node 호환성을 검증한다.

별도 `brodcasting_part04_test`와 `brodcasting_part04_lab`, Compose18.6/loopback5544, API3004/client5184를 사용한다.3단계 파일/DB/학습 명령을 바꾸지 않는다. test는 고유 schema/role만 정리한다. migration·seed·역할 설정은 operator, API는 제한 `part04_app` 역할이다. 역할·schema 식별자는 내부 허용 목록, 데이터는 바인딩한다.

- users: UUID PK, username unique/NOT NULL(소문자 ASCII 문자로 시작하는3~24자, 나머지 숫자/밑줄), password_hash NOT NULL. 응답은 `{id,username}`만 반환한다.
- broadcasts:3단계6개 fixture와 제약·인덱스. favorites는 users/broadcasts FK와 복합PK. 서버 고정 demo-user를 제거한다.
- rooms: id `r1/r2`, title, notice(일반 텍스트500자 이하). room_admins(user_id,room_id) 복합PK/FK. 가입 입력에 역할/관리자 필드는 없다. operator의 `grant-admin --username NAME --room r1`만 실습 권한을 부여한다.
- sessions: connect-pg-simple 공식 table.sql과 호환되는 sid/sess/expire, PK와 만료 인덱스. API는 테이블을 만들지 않는다. users SELECT/INSERT, broadcasts SELECT, favorites SELECT/INSERT/DELETE, rooms SELECT 및 notice 컬럼 UPDATE, room_admins SELECT, sessions CRUD만 허용한다. 비밀번호 해시·세션 테이블을 공개 응답/로그로 반환하지 않는다.

## 인증과 세션 계약

PasswordService.hash/verify는 라이브러리 Argon2id(메모리19456KiB, timeCost2, parallelism1)를 사용한다. salt는 라이브러리가 생성한다. 비밀번호는 Unicode15~128자, trim/변형/조합 강제 없이 받는다. 해시·평문·CSRF·세션 원문은 기록에 남기지 않는다. 존재하지 않는 계정도 dummy hash를 검증하고 잘못된 로그인은 같은401이다. 이것으로 모든 시간 차이를 제거했다고 주장하지 않는다.

쿠키 이름 `brodcasting.part04.sid`, HttpOnly, SameSite=Lax, path=/, 로컬 HTTP에서 Secure=false. SESSION_SECRET은 실행 시 생성한32byte 난수의64hex를 요구하며 fallback이 없다. 쿠키에는 세션 ID만, 서버에는 userId/authenticatedAt/csrfToken을 저장한다. express-session의 resave=false, saveUninitialized=false, rolling=false; PostgreSQL store disableTouch=true, createTableIfMissing=false. 실제30분 절대 만료를 서버도 확인한다. 로그인 시 regenerate 후 userId/시간/새 CSRF를 저장하고 save 완료 뒤 응답한다. 옛 쿠키·옛 CSRF가 새 인증에 쓰이지 않아야 한다. 사용자 존재를 요청마다 DB에서 확인한다.

로그아웃은 destroy 완료 후 쿠키를 같은 path로 지우고204다. 완료 이후 시작한 옛 세션 요청을 거부한다. 이미 인가를 마친 진행 중 요청을 취소하는 보장은 하지 않는다. API 프로세스 재시작 뒤 세션 유지와 로그아웃 뒤 재시작해도 폐기 유지가 검증 대상이다. 소켓 인증/기존 연결 폐기는5단계이며 이 HTTP 코드로 완료됐다고 보지 않는다.

csrf-sync의 기본 세션 동기화 토큰을 `X-CSRF-Token` 헤더에서 검사한다. GET/HEAD/OPTIONS 외 모든 API 요청, 가입·로그인·로그아웃도 보호한다. 토큰을 쿠키/URL에서 읽거나 비교 함수를 직접 만들지 않는다. Origin이 있으면 정확한 client origin만 허용하고 다른 origin은403이다. CORS 허용을 추가하지 않고 Vite의 같은 origin 프록시를 쓴다. 기본 trust proxy=false다. 실제 브라우저의 SameSite/CORS 차단은 미실행으로 남긴다.

POST 가입/로그인은 IP별60초10회,11회부터429(Retry-After, 정제한 JSON). 라이브러리 기본 IP key와 단일 프로세스 MemoryStore를 사용한다. 재시작 초기화·다중 인스턴스·분산 시도의 한계를 명시한다. 테스트만 짧은 window/작은 limit을 주입할 수 있으며 main 설정은 고정한다.

## HTTP 계약

모든 응답 no-store. JSON8kb, 값/변환 전 미정의 키/중복 query/잘못된 id는400, 큰 JSON413, 비어 있지 않은 다른 body 형식은 파싱 전에400. 정상 형식의 인증 없는 보호 요청401, 로그인했지만 다른 소유자/방의 권한403, 없는 공개 방송/방404, 정제한 DB 오류503. CSRF/Origin 실패403은 Guard 전에 발생할 수 있다.

| 메서드·경로 | 계약 |
| --- | --- |
| GET /api/auth/session | `{user:User\|null,csrfToken:string}`. 익명 토큰 발급도 서버 세션에 저장 |
| POST /api/auth/register | `{username,password}`만,201 `{id,username}`. 중복409. 자동 로그인하지 않음 |
| POST /api/auth/login | 같은 입력,200 SessionView. 실패401. SID/CSRF 교체 |
| POST /api/auth/logout | 인증+CSRF,204. 폐기 완료 뒤 응답 |
| GET /api/broadcasts 및 /:id |3단계 Page/행 계약. 익명 favorite=false, 인증 사용자만 자신의 favorite. favoritesOnly=true는 인증 필수 |
| GET /api/users/:userId/favorites | UUID 주체와 세션 사용자 일치 필수. Page, 검색/정렬/limit/offset은3단계와 같음, favoritesOnly는 true로 고정 |
| PUT/DELETE /api/users/:userId/favorites/:id | 본인만, 빈 본문/빈 JSON만.200 `{id,favorite}`. 재시도 멱등 |
| GET /api/rooms/:id | 공개 `{id,title,notice,canEdit}`. canEdit은 현재 서버 권한으로 계산 |
| PUT /api/rooms/:id/notice | 인증된 해당 방 관리자만 `{notice}`.200 Room. 일반/다른 방 관리자403과 DB 불변 |

Guard는 인증을 검사해 request.actor에 현재 User를 설정하고, Service는 actor/자원/행위를 검사한다. favorites repository는 항상 actor id를 바인딩한다. 공지 UPDATE에도 room_admins 조건을 넣어 화면 플래그에 의존하지 않는다. 타인의 UUID를 직접 넣거나 body/query/헤더로 역할을 전달해도 권한을 얻지 못한다.

## 화면과 교재

3단계 페이지 목록/검색/정렬을 유지하고 위에 간결한 가입·로그인/로그아웃 영역, 아래에 방 선택·공지/관리자 편집을 둔다. 기존 팔레트·글꼴·레이아웃을 이어간다. API가 준 User/권한만 표시하며 인증값을 localStorage에 저장하지 않는다. 비밀번호 입력은 제출 후 비우고 토큰은 메모리만 사용한다. 인증 변경 시 이전 GET/쓰기 결과를 무시하며 목록/권한을 다시 조회한다.401은 재인증 안내,403은 권한 안내, 연결 실패는 결과 미확정과 재조회로 구분한다. 공지 초안은 실패 시 보존하고 다른 계정 로그인 후 자동 재전송하지 않는다. 모든 제목/공지/이름은 React 텍스트로 표시한다.

시작 코드는 완성한3단계 DB/HTTP/UI 선수 기능을 제공하고 PasswordService/AuthService/AuthGuard/접근 정책만 fail-closed 과제로 남긴다. 참고 완성본은 별도 자체 lock/workspace다. A해싱/B세션/C소유권·방 권한,3주 배분·설명3개·독립 ‘모든 기기 로그아웃’ 설계/구현(정답 없음), 제출·미실행 브라우저 목록을 제공한다. F2는4단계 실제 HTTP 경계와 연결하되 전용 브라우저 실습 완료로 세지 않는다.

## 검증과 게시

실제 PostgreSQL18.6 Actions service를 우선 사용한다. 호스트 UID 제한의 우회나 Docker/브라우저 설치를 시도하지 않는다. 해시 무작위 salt/올바른·틀린 비밀번호, DB 제약/최소 권한, 실제 opaque 쿠키 jar의 정상/위조/고정/만료/폐기/재기동, 타인 UUID/다른 방 관리자/미정의 role/SQL 문자열, CSRF 누락·틀림·다른 세션·옛 토큰·다른 Origin, 제한429와 실패 후 DB 불변을 RED→GREEN으로 확인한다. jsdom은 인증 전환·늦은 결과·초안·텍스트 출력과 실제 브라우저의 차이를 표시한다.

완성본 독립 복사 npm ci/typecheck/build/API/개발 프록시, 시작 코드의 의도된 실패 수집, 이전0~3단계 및 Node 정책을 확인한다. 한 번의 새 컨텍스트 전체 리뷰 뒤 Important/Critical은 한 번의 재현 테스트·수정·전체 회귀로 처리한다. 완료 시 main 최신 SHA·force false로 게시하고 제목만 알린다. 다음은 원본5단계이며 BunkerWeb은 전체 맨 마지막이다.
