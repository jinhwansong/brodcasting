# 온에어 라운지 디자인 시스템

사용자가 UI를 중요하게 보고 화면별 임시 스타일 대신 디자인 시스템을 먼저 만들라고 요청했다. 진행 중인 알림5주 코드와 검사는 보존하고 이 작업을 먼저 수행한다. 기존 SOOP/치지직 탐색 방향·어두운 바탕·민트 강조를 유지한다. 추가 중간 승인 없이 제작하도록 위임한 범위에서 설계·구현·실제 화면 검증까지 진행한다.

## 제품과 시각 기준

방송을 찾고 시청하며 채팅하는 한국어 사이트다. 미디어가 중심이고 공통 요소는 조용하게 받친다. 넓은 화면은 왼쪽 채널 탐색/가운데 썸네일 목록, 시청은16:9 영상/오른쪽 채팅이다. 휴대폰에서는 영상→방송 정보→채팅→공지 순서다. 안내 박스를 반복해 방송을 밀어내지 않는다.

- 기본 팔레트: 바탕 #0E1015, 탐색 #151821, 표면 #1E222D, 글자 #F3F5F8, 보조 글자 #A4ADBE, 강조 #78E1CD. 오류와 실제 LIVE는 별도의 코랄 계열 의미 색을 쓴다. 샘플 표시는 중립색이다.
- 글자는 설치된 한글 sans-serif를 사용한다. 외부 폰트 요청은 만들지 않는다. 화면 제목28~30px·영역 제목20px·방송 제목15~16px·본문14px·설명12px를 기본으로 삼는다. 사용자 동작에 필요한 안내를9~10px로 줄이지 않는다.
- 간격은4/8/12/16/20/24/32/40/48px, 조작 높이는40px·작은 조작36px·휴대폰44px, 둥근 모서리는 조작8px·미디어/패널12px·작은 배지4px를 기준으로 한다. 장식 그림의 색과 미디어 내부 색은 UI 의미 색과 구분한다.
- 색으로만 상태를 알리지 않는다. 오류/로딩/비활성/선택/완료를 글과 접근성 속성으로 함께 표시한다. 포커스는 눈에 띄고 reduced-motion을 따른다.

## 코드와 적용 범위

공통 원본은 apps/broadcast/client/src/ui다. tokens.css는 의미 있는 값의 유일한 원본, system.css는 기본 요소와 공통 상태, components.tsx는 네이티브 요소를 감싼 작은 React 컴포넌트다. 외부 UI 의존성·전역 상태 라이브러리·독립 패키지 배포를 추가하지 않는다. CSS layer로 화면 배치와 공통 요소의 우선순위를 명시한다.

Button(기본/보조/조용한/위험·진행 중), IconButton(필수 이름), TextField/TextAreaField(연결된 label·안내·오류), Badge(샘플/실제LIVE/상태), InlineNotice, EmptyState를 제공한다. 대화상자는 native dialog로 키보드·Escape·포커스 복귀를 유지한다. 방송 카드는 제품 조합 컴포넌트로 한 곳에서 만들고 목록과 디자인 전시 화면이 같은 코드를 사용한다.

`#/design-system`에서 실제 컴포넌트·상태·색상·글자·간격·방송 카드 조합을 확인한다. 예제 동작은 예제라고 명시하고 실제 서비스 건수나 방송으로 가장하지 않는다. 로그인·팔로우·공지·채팅·WebRTC의 기존 동작과 권한 검사는 유지한다.

독립 교재의 외부 파일 링크 금지를 지킨다. WebRTC 시작/완성본에는 검증된 제공 UI만 동기화하고 ICE·방 권한의 학습 TODO는 보존한다. 알림5주 UI에도 동일 원본의 내부 복사본을 사용한다. 예전0~11단계 교재 전체를 시각 변경 때문에 자동 재작성하지 않는다.

## 완료 판단

공통 요소의 이름·label/오류 연결·진행 중 중복 동작 차단·예제 상호작용을 검사한다. 기존 사이트 행동13검사와 WebRTC19단위/9실제 신호 검사를 유지한다. 실제 브라우저에서 전시 화면/목록/시청/계정, 데스크톱/360px·키보드·오류/로딩을 확인하고 스크린샷을 남긴다. 저장소 밖 새 설치·빌드와 교재 제공 UI 일치도 확인한다. 학습자는0·미시작이다.

자체 검토: 이미 사용자가 고른 다크/민트 방향을 유지한다. 색 변수만 만든 것으로 완료하지 않고 실제 화면에 적용한다. 제품 본문에는 개발용 토큰 이름을 노출하지 않고 전시 화면에서만 설명한다. 백엔드·세션·큐 동작을 시각 변경에 섞어 바꾸지 않는다.
