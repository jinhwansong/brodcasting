# 7~11단계 연속 제작 계획

사용자 지시: 11까지 제작·검증·커밋·푸시. 설명은 중학생도 읽을 수 있는 말로 쓴다. 순차 실행하며 학습자는 0단계·미시작을 유지한다.

## 범위와 결정

- 7: 서버 없이 재현 가능한 React 채팅 실험실. 10/100/500건/초, 보관 1,000행, 대기 200행, 화면 가상화, 묶음 갱신, 읽던 위치·새 글 표시·정리. 비교용 전체 표시도 같은 보관 상한. 실제 기기 성능 수치는 사용자의 후속 브라우저 검증에 남긴다.
- 8: 7단계 실험실에 native video를 결합. 직접 만든 영상·자막, 이벤트에 따른 상태, 자동재생 거절·오류·재시도·방송 전환 정리. P2P/그리드와 화질 조절·재생 지연은 서로 다른 개념으로 설명. 실제 P2P/CDN/송출 구축은 요청 범위가 아니다.
- 9: 6단계의 인증·DB·Socket.IO를 선수 코드로 재사용하는 로컬 부하 실험. 다중 클라이언트, 고정 조건과 중단 상한, 원시 지연·오류·자원·회복 기록, 같은 조건의 개선 비교. 외부 주소 금지.
- 10: 로컬 HTTPS/WSS 프록시와 제한 역할 DB, 상태 확인·정제 로그·백업/새 DB 복원·실패 롤백. 새 설치 경로와 실제 복구를 검증. 공개 배포·유료 자원·BunkerWeb은 포함하지 않는다.
- 11: 실제 변경 요구를 읽고 영향 범위를 적는 실행 과제와 공개 검사, 3개 사례의 빈 제출 양식. 학습자 경험·성과는 제작자가 대신 적지 않는다.

7/8은 별도 화면에서 UI와 미디어 병목을 분리한다. 9/10은 기존 6단계 서버를 복사하거나 명시한 선수 경로로 실행하며 보안을 바꾸지 않는다. 새 의존성은 필요한 도구에 한정하고 기존 exact 버전을 유지한다. root 기본 명령과 사용자 소유 docs/PROJECT_PLAN.md·docs/REMAINING_WORK.md는 건드리지 않는다.

## 파트마다 해야 할 일

1. 공개 계약·실패 검사부터 작성하고 TODO에서 예상 실패를 확인한다.
2. 분리된 참고 구현과 실제 실행 경로를 작성한다. 새 로직의 정상·경계·실패·정리를 검사한다.
3. 시작 코드에는 이번 과제의 핵심 TODO만 남긴다. 선수 코드는 제공한다.
4. README에 목적·쉬운 비유·낱말 뜻·파일 지도·명령·예상 화면·작은 실습 순서를 쓴다. 해설은 첫 시도 뒤에 읽게 한다. 설명 3개·독립 변경·빈 제출·미실행 브라우저 양식도 둔다.
5. 타입/빌드·공개 검사·시작 코드 실패 분류·독립 실행을 확인하고 원시 결과를 남긴다. 회귀는 영향 범위에 맞춰 한 번 수행한다.
6. 순차 자체 검토와 단순화 뒤 검증 문서를 작성하고 커밋·푸시·원격 SHA와 CI를 확인한다. 독립 에이전트 리뷰를 수행했다고 주장하지 않는다.

## 자체 검토

가상화의 DOM 상한과 데이터 보관 상한을 나눈다. 타이머로 늦은 시간을 한꺼번에 따라잡지 않는다. 미디어 Promise의 이전 방송 결과가 새 방송을 덮지 않게 한다. 부하 발생기의 시계로 ack 왕복을 측정하고 송수신 수를 구분한다. 복구는 원본 학습 DB를 덮지 않고 새 소유 DB에서 증명한다. 테스트만으로 학습 통과를 적지 않는다.
