# 알림 7주·프론트 보안 3강·통합 방송 사이트 계획

> 사용자2026-10-21 명시 범위: 알림·프로세스·큐7주 + 프론트 보안3강. 빠뜨린 작업은 실제 브라우저 검증이라고 확인했다. 후속 선택에서 ‘교재와 함께 숲 느낌의 UI·목록·시청·채팅·알림이 연결된 사이트도 만들기’를 명시했다. 중간 승인 없이 순차 제작·검증·커밋·푸시한다. BunkerWeb은 이번 범위에서 제외한다.

## 목표와 고정 선택

기능별 교재를 실제 실행 가능한 단위로 완성하고, 마지막에 하나의 사이트에서 목록→시청→채팅·팔로우→내 알림을 연결한다. 실시간 영상 송출·트랜스코딩·P2P/CDN 구축·유료 인프라·공개 운영은 포함하지 않는다. 제공된 자체 샘플 영상임을 시청 화면에서 명시한다. 숲의 로고·화면을 복제하는 대신 방송 탐색과 시청 흐름을 참고한 독자적인 UI를 만든다.

기존 React·TS·Vite·Nest·PostgreSQL·직접 SQL·검증된 세션/CSRF/Socket.IO를 재사용한다. 큐에만 BullMQ·Redis를 추가하고 착수 시 공식 문서와 실제 버전을 확인·고정한다. 새 공용 프레임워크·별도 인증 방식·상태 관리 라이브러리는 추가하지 않는다. 의도된 labs TODO와 reference 분리, 독립 설치, 학습0·미시작을 유지한다.

## 실패와 데이터 경계

- API는 기존 세션으로 확인한 본인의 알림만 읽거나 읽음 처리한다. 클라이언트가 보낸 userId를 신뢰하지 않는다.
- 큐 작업은 정해진 최소 ID·타입만 전달하고 비밀번호·쿠키·토큰을 넣지 않는다. DB 저장과 큐 투입 사이 실패는 영속 기록/재처리로 설명하고 직접 재현한다.
- 실제 메일·알림 push 수신처를 호출하지 않는다. 가짜 발송과 실제 사이트 내부 알림 저장을 구분한다.
- 종료·재시작은 소유 프로세스/컨테이너만 제어한다. 기존 사용자 DB/볼륨/역할은 삭제하지 않는다. 실험 컨테이너·schema·queue는 고유 이름과 finally 정리를 사용한다.
- 브라우저 보안 경고는 우회하지 않는다. 인증서 신뢰가 필요한 검증은 신뢰 설정/사용자 조작 요구를 분리하고 미검증을 성공으로 적지 않는다.
- ms와 메모리는 실제 수집할 수 있는 것만 기록한다. 현재 CUA의 읽기 전용 범위에서 performance는 제공되지 않으므로 DOM 상한·직접 조작 증거와 정량 성능 미확인을 구분한다.

## 통합 UI 설계 계약

방송 목록은 썸네일과 진행자·제목·카테고리·팔로우를 중심으로 구성한다. 넓은 화면에는 간결한 탐색 사이드바와 여러 열의 목록, 시청 화면에는 큰16:9 플레이어와 오른쪽 채팅을 둔다. 좁은 화면에는 상단 탐색·한두 열 목록과 플레이어 아래 채팅을 제공한다. 로그인과 알림은 어디서든 접근 가능하며 진행 중/비로그인/거부/빈목록/연결끊김/재시도 상태를 표시한다.

이름은 독자적인 ‘온에어 라운지’로 작업한다. 흰색 #FFFFFF와 옅은 회청 #F3F6FA를 바탕으로 먹색 #172231 글자, 파랑 #2658E8 탐색 강조, 붉은색 #E63946 LIVE 표시를 쓴다. 기본 글꼴은 운영체제 한글 sans-serif이며 외부 폰트·트래킹을 요구하지 않는다. 가짜 시청자 수는 ‘샘플’임을 구분한다. 시청 페이지에는 학습용 샘플 영상 표시를 남기고 실제 방송 중인 것처럼 가장하지 않는다. 둥근 패널을 반복하기보다 썸네일·미디어·텍스트의 위계를 사용한다.

## 완료와 게시

검사 먼저 실패→구현→같은 검사 통과를 기록하고 관련 회귀·새 소스 설치를 확인한다. 각 완성 단위를 소유 경로만 게시하며 기존 미추적 사용자 문서 두 개는 제외한다. 최종 통합 사이트까지 끝나기 전 전체 완료라고 말하지 않는다. 브라우저 실험은 관찰한 동작만 기록하고 학습자 제출에 제작자 성과를 채우지 않는다.
