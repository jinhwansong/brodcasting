# 실습을 처음 시작할 때 읽는 안내

이 교재는 코드를 빨리 복사하는 연습이 아닙니다. 작은 기능을 직접 만들어 보고 **왜 그렇게 움직이는지 설명하는 연습**입니다. 현재 학습 상태는 0단계·미시작입니다. 다음 단계의 완성 코드를 한꺼번에 펼칠 필요는 없습니다.

## 한 번에 이렇게 해 보세요

1. 현재 파트 README를 읽습니다. 쉬운 설명인 lesson.md가 있으면 먼저 읽습니다.
2. ‘이렇게 될 것 같다’를 3~5문장 적습니다. 정답을 맞히는 시험이 아니므로 모르는 것도 적습니다.
3. 파일 지도에서 내 과제 하나를 고릅니다. TODO는 아직 내가 채워야 할 빈자리라는 뜻입니다.
4. 한 가지를 고친 뒤 실행합니다. 실패한 검사 이름과 실제 화면을 봅니다.
5. 막히면 질문을 작게 만듭니다. ‘전부 짜 줘’보다 ‘이 입력에서 왜 빈 배열이 나오는지 힌트를 줘’가 연습에 도움이 됩니다.
6. 첫 시도 뒤에만 해설을 펼칩니다. 비교용 완성본은 reference-solutions/에 따로 있습니다.
7. 마지막에 세 가지를 내 말로 적습니다. **무엇을 고쳤나 / 왜 고쳤나 / 어떻게 확인했나.**

## 명령이 낯설다면

**터미널**은 컴퓨터에 글로 명령을 내리는 창입니다. 이 저장소의 루트 폴더에서 명령을 실행하라는 말은 package.json이 있는 E:\code\brodcasting 위치에서 시작하라는 뜻입니다. 다른 컴퓨터에서는 내려받은 저장소 위치가 다를 수 있습니다.

- `npm ci`: 기록된 버전 그대로 필요한 도구를 설치합니다. 처음 준비할 때 씁니다.
- `npm run dev...`: 고친 화면을 보면서 연습하는 서버를 켭니다. 중지는 보통 Ctrl+C입니다.
- `npm run typecheck...`: TypeScript에서 값의 모양이 맞는지 검사합니다.
- `npm run build...`: 실행·배포용 파일을 만듭니다.
- `npm run check...`: 정해 둔 행동을 코드가 지키는지 자동 검사합니다.

명령의 뒷부분은 파트마다 다르므로 해당 README의 명령을 그대로 확인하세요. 필요한 Node 버전과 첫 설치는 루트 README를 따릅니다. DB가 필요한 파트는 전용 실습 DB를 준비하고 개인·회사 DB를 넣지 않습니다.

## 빨간 실패가 항상 준비 오류는 아니에요

시작 코드에는 일부러 빈자리가 있습니다. ‘예상은 100인데 실제는 0’ 같은 실패는 그 빈자리를 채우라는 신호일 수 있습니다. 반대로 ‘모듈을 찾지 못함’, ‘DB 연결 안 됨’, 문법 오류는 먼저 준비나 코드를 바로잡아야 합니다. 둘을 섞어서 ‘원래 실패하는 실습’이라고 넘기면 안 됩니다.

검사가 모두 통과해도 학습이 저절로 끝나지는 않습니다. 설명 질문과 작은 독립 변경을 직접 해야 합니다. **제작자가 검사했다**는 기록과 **내가 실습했다**는 기록도 구분합니다.

## 기록은 짧고 구체적으로

‘잘 됐다’보다 ‘100개를 남기게 바꾼 뒤 150개를 넣었더니 마지막 100개만 남았다’가 좋습니다. 측정하지 않은 속도나 해 보지 않은 브라우저는 ‘미확인’으로 적습니다. AI가 한 부분과 내가 고른 부분도 나눠 적습니다.

한 번에 이해가 안 되면 작은 숫자나 종이 그림으로 먼저 해 보세요. 1,000개 배열 문제를 10개로 줄여도 원리는 같습니다.
