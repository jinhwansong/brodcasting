# 4단계 해설

첫 예상과 구현을 제출한 뒤 비교하세요. [과제](README.md)의 독립 ‘모든 기기 로그아웃’ 정답은 이 문서에 없습니다.

<details>
<summary>A · 같은 원문, 다른 해시</summary>

해시 문자열은 비밀번호 복호화용 값이 아닙니다. 라이브러리가 매번 salt를 만들므로 같은 원문도 서로 다른 문자열이 됩니다. 로그인은 새 해시 문자열과 DB 문자열을 직접 비교하는 대신 라이브러리 verify로 저장된 설정·salt를 이용합니다. 설정과 원문은 서로 다른 입력이며 trim하면 공백이 있는 원문을 바꿉니다. 손상된 저장 형식의 예외를 무조건 false로 바꾸면 시스템 손상을 일반적인 인증 실패로 숨깁니다.

현재 검사는 문자열 파라미터의 직렬화 순서에 의존하지 않고 알고리즘·버전·m/t/p 값을 확인합니다. 사용자 응답은 User만 반환하며 passwordHash를 직렬화하지 않습니다.
</details>

<details>
<summary>B · 세션의 수명과 저장</summary>

익명 session 조회는 CSRF 토큰을 발급하고 저장할 수 있습니다. 로그인은 기존 SID를 재사용하지 않고 regenerate 후 userId·authenticatedAt·새 토큰을 저장한 뒤 응답합니다. 현재 사용자 확인은 DB 사용자 존재와 절대 수명을 확인합니다. 기존 세션 조회를 무조건 save하면 동시에 폐기된 SID를 upsert로 되살릴 수 있어, 조회 때마다 저장하지 않습니다.

store의 disableTouch와 rolling=false로 요청마다 절대 수명을 늘리지 않습니다. 쿠키 유효기간과 서버 만료를 모두 검사합니다. API 재시작은 같은 DB·secret을 쓰면 세션이 유지됩니다. 로그아웃은 store destroy와 cookie clear를 기다리므로 이후 시작한 옛 쿠키 요청을 거부합니다. 이미 인가를 마친 진행 중 요청까지 취소한다고 보장하지는 않습니다.

CSRF 토큰은 메모리에 있고 unsafe 요청 헤더로 보냅니다. HttpOnly는 JS의 쿠키 읽기를 줄이고 CSRF/Origin과는 다른 경계입니다. CORS 허용이 없다는 사실만으로 서버 쓰기가 안전하다고 판정하지 않습니다. 실제 브라우저의 전송·차단 증거는 별도로 남깁니다.
</details>

<details>
<summary>C · 인증된 주체와 자원</summary>

Guard가 현재 세션을 확인해 actor를 설정합니다. Service는 URL UUID와 actor를 비교하고 타인을 거부합니다. UUID는 대소문자 표기가 달라도 같은 ID일 수 있습니다. DB favorite 키에는 현재 주체를 바인딩합니다. 방 권한은 room_admins에서 계산한 canEdit과 UPDATE 조건에서 모두 확인합니다. 화면에서 버튼·role을 조작해도 서버의 사실은 바뀌지 않습니다.

권한 검증은 상태 코드뿐 아니라 실패 후 대상 행이 그대로인지 확인합니다. CSRF·Origin·입력 계층이 먼저 거부할 수 있으므로 어떤 경계가 작동했는지도 기록합니다. DB 운영자와 API 제한 역할은 서비스 사용자와 다른 개념입니다.
</details>

<details>
<summary>화면 · 초안과 늦은 응답</summary>

인증 동작 전후 epoch가 바뀌면 이전 계정의 읽기·쓰기 완료와 finally를 무시합니다. 방 선택 revision은 이전 방 응답을 무시합니다. AbortController만으로 이미 끝난 서버 작업과 모든 늦은 완료를 막을 수는 없습니다. 저장 결과를 받지 못해도 서버가 반영했을 수 있으므로 자동 재전송이나 성공 표시 대신 재조회를 안내합니다.

401은 같은 계정 재인증 기회를 위해 초안을 유지합니다. 다른 계정이면 이전 초안을 지우며 명시적 로그아웃 성공도 지웁니다. 403은 권한을 다시 읽고 초안은 보존합니다. 일반 텍스트는 React 자식으로 표시하고 HTML로 삽입하지 않습니다. 비밀번호 입력은 요청 완료 후 비웁니다. 토큰·세션을 localStorage에 쓰지 않습니다.
</details>

## 틀린 접근을 점검하기

- ‘해시가 달라서 로그인 불가’: 문자열 비교와 verify 입력을 구분합니다.
- ‘로그아웃 버튼을 눌렀으니 완료’: store destroy 성공과 불명확한 연결 실패를 구분합니다.
- ‘새 계정에서 저장 버튼이 풀림’: 이전 계정 요청의 finally가 현재 busy를 해제했는지 봅니다.
- ‘403이면 공지를 비움’: 초안과 서버 원본을 구분하고 권한을 재조회합니다.
- ‘테스트 실패는 모두 과제’: 수집·모듈·연결·시간 초과 오류는 환경 문제부터 해결합니다.
