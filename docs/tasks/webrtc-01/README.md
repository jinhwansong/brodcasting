# WebRTC — 내 화면을 다른 브라우저로 보내기

샘플 파일 재생과 실제 송출은 다릅니다. 이번에는 **내 브라우저가 만든 영상을 다른 탭에 보내는 실습**을 합니다. 로그인·사이트·DB·자원 정리는 제공 코드입니다. [쉬운 설명](lesson.md)을 먼저 읽고 [제출 양식](submission.md)에 예상부터 적으세요.

## 내가 고칠 두 곳

| 과제 | 파일 | 해야 할 일 |
| --- | --- | --- |
| A | labs/webrtc-01/client/src/rtc-client.ts의 gatherIce | 연결 후보 수집 완료를 기다립니다. 취소·8초 제한·이벤트 정리도 처리합니다. |
| B | labs/webrtc-01/server/src/rtc-rooms.ts의 authorizeSignal | 같은 방의 송출자→시청자 offer, 시청자→송출자 answer만 허용합니다. |

인증을 끄거나 모든 신호를 허용해서 검사를 통과시키면 안 됩니다. 비밀번호·카메라 선택·방 식별자를 가짜 성공 값으로 바꾸지 않습니다.

## 실행 순서

지원되는 Node와 Docker Desktop Linux 엔진을 준비합니다. 먼저 이 폴더에서 설치합니다. 저장소 루트에서 학습 답안을 자동으로 복사하지 마세요.

```sh
cd labs/webrtc-01
npm ci
npm run typecheck
npm run check
```

처음에는 TODO 때문에19개 중13통과·6의도된 실패입니다. 공개 검사는 서버7개·클라이언트12개입니다. 모듈 설치 실패나 Docker 오류는 과제 실패와 구분하세요. 검사 파일을 지우거나 결과 숫자를 고치지 않습니다.

1. 연결 후보 수집 중에 종료 버튼을 누르면 어떻게 되어야 할지 예상합니다.
2. A를 구현한 뒤 검사를 다시 실행합니다.
3. B를 구현합니다. 올바른 두 방향은 허용하고 다른 방·다른 방향·외부 소켓은 거부합니다.
4. 모든 단위 검사가 통과하면 `npm run check:integration`으로 실제 일회용 DB·로그인·소켓 검사를 실행합니다. Docker를 사용하고 자신이 만든 컨테이너만 정리합니다. 외부 방송은 접속하지 않습니다.
5. [사이트 실행 안내](../../../apps/broadcast/README.md)의 DB 준비를 이 학습 폴더의 `.env`와 `npm run db`, `npm run dev:api`, `npm run dev`로 수행합니다. 기존 사용자 DB 대신 별도 실습 DB를 사용합니다.
6. [쉬운 설명](lesson.md)의 두 탭 실습을 직접 합니다. 참고 완성본의 브라우저 검증은 내 실습 통과가 아닙니다.
7. [해설](explanation.md)을 비교하고 설명3개와 독립 변경을 제출합니다.

완성된 사이트는 `apps/broadcast`, 독립 참고 완성본은 `reference-solutions/webrtc-01`입니다. 두 폴더도 같은 포트를 사용하므로 한 번에 하나만 실행합니다. 학습 진도는 여전히0·미시작입니다.
