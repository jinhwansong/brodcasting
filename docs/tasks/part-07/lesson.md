# 코드 전에 읽는 쉬운 설명

## 책장과 펼친 페이지

책 1,000권을 모두 책상에 펼치면 자리가 모자랍니다. 책장에 보관하고 지금 읽는 몇 권만 꺼내면 됩니다. 채팅도 비슷합니다.

- **메모리**: 프로그램이 작업하는 동안 쓰는 책장입니다. 배열에 글을 계속 넣으면 책장이 계속 커집니다.
- **DOM**: 브라우저가 화면을 만들기 위해 보관하는 글·버튼 등의 구조입니다. 같은 글을 배열에 넣는 일과 화면에 그리는 일은 서로 다릅니다.
- **가상화**: 목록 전체가 있는 것처럼 스크롤 길이를 만들고, 지금 보이는 부분만 실제로 그리는 방법입니다. 여기서 ‘가상’은 가짜 데이터라는 뜻이 아닙니다.
- **묶음 갱신**: 택배가 하나 올 때마다 정리하는 대신 잠깐 모아서 한 번에 정리하는 방법입니다. 너무 오래 모으면 늦어지므로 기다리는 시간도 제한합니다.

가상화만 켜고 배열에 끝없이 넣으면 책상만 비었을 뿐 책장은 계속 커집니다. 그래서 보관 개수와 화면에 그릴 개수를 따로 제한합니다.

## 초당 500개는 실제 사용자 500명이 아니에요

이번 글은 내 컴퓨터 안에서 만듭니다. 로그인·통신·서버·DB는 지나지 않습니다. ‘이 화면이 글을 얼마나 잘 처리하는지’ 보는 실험입니다. 실제 접속자가 서버에 주는 부담은 9단계에서 따로 확인합니다.

## 읽던 자리를 왜 지켜야 할까요?

누군가에게 온 편지를 읽는데 새 편지가 왔다고 책을 덮어 버리면 불편합니다. 스크롤도 같습니다. 아래를 보고 있을 때만 새 글을 따라갑니다. 위를 읽고 있을 때는 ‘새 메시지’ 버튼으로 알려 줍니다. 보관 범위를 넘겨 편지를 꺼내 놓을 수 없게 되면 그 사실을 말해 줘야 합니다.

## 20분짜리 첫 실습

1. 완성 코드를 보지 말고 README의 예상 세 문장부터 씁니다.
2. window.ts를 열어 입력과 반환 모양을 읽습니다. 전체 앱을 한 번에 이해할 필요는 없습니다.
3. 종이에 작은 수 10개로 먼저 풀어 봅니다. 컴퓨터의 1,000개 문제도 원리는 같습니다.
4. 검사에서 실패한 이름 하나만 골라 고칩니다. 에러 문장을 그대로 복사해 두고 내 말로 뜻을 적습니다.
5. 끝나면 ‘뭘 바꿨는지 / 왜 바꿨는지 / 뭘 확인했는지’를 한 문장씩 적습니다.

‘빠르다’는 느낌도 출발점은 됩니다. 하지만 결과에는 기기와 조건, 측정 기록이 필요합니다. 측정하지 않았다면 ‘아직 모른다’고 적는 것이 맞습니다.
