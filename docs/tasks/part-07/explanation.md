# 첫 시도 뒤 읽는 해설

<details><summary>A — 최근 글을 남기는 이유</summary>

이 화면은 원본 창고가 아니라 읽기용 작은 책상입니다. 이전 글과 새 글을 합친 뒤 끝에서 1,000개만 고릅니다. 새 배열을 만들어야 이전 화면 상태도 안전합니다. DB 이력까지 삭제하는 정책과는 별개입니다.

</details>

<details><summary>B — 창문으로 보는 목록</summary>

스크롤을 48로 나누면 첫 번째로 보이는 줄을 짐작할 수 있습니다. 화면의 8줄에 앞뒤 3줄을 더해 최대 14줄을 그립니다. 처음·끝에서는 목록 밖으로 나가지 않게 범위를 줄입니다. 줄 높이는 항상 48px이어야 이 계산이 맞습니다. 긴 글 전체를 읽는 화면이나 가변 높이 목록으로 확장할 때는 다른 설계가 필요합니다.

</details>

<details><summary>C — 잠깐 모으고 반드시 치우기</summary>

생성 타이머와 반영 타이머는 별개입니다. 기다리는 글은 200개, 화면 보관은 1,000개입니다. 한 번 시작하면 60초 뒤 멈추며 정리 함수가 세 타이머와 대기 글을 비웁니다. 방 컴포넌트의 key를 바꾸면 이전 방을 끝내고 새 방을 만듭니다. 입력과 목록은 별도 상태여서 새 글이 입력 내용을 지우지 않습니다.

</details>

독립 변경의 읽기 잠금 정답과 실제 기기 성능 수치는 싣지 않습니다.
