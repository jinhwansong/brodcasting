# 용어를 책상으로 바꿔 보기

알림 버튼을 눌렀는데 긴 계산 때문에 다른 요청까지 기다리면 답답합니다. 그래서 먼저 ‘누가 어디서 일하는가’를 구분합니다.

**프로세스는 실행 중인 프로그램 한 개**입니다. 사무실 하나라고 생각하세요. 그 안의 **스레드는 일을 진행하는 줄 하나**입니다. Node에는 JavaScript를 실행하는 기본 스레드 외에도 내부 일을 처리하는 스레드가 있습니다. ‘Node는 스레드가 딱 하나’라고 외우면 틀립니다.

이벤트 루프는 책상 위에 온 다음 일을 꺼내는 진행 방식입니다. 지금 큰 계산을 끝내지 않으면 다음 일의 차례가 오지 않습니다. Promise는 ‘이후에 결과를 받을 약속’이지 계산할 직원을 새로 고용하는 명령이 아닙니다. async 함수 안에서도 긴 반복문을 계속 돌면 그 스레드가 바쁩니다.

cooperative는 숙제 1만 문제를 한 번에 다 풀지 않고, 일부를 풀 때마다 옆 사람의 짧은 질문을 받는 방식입니다. **같은 스레드에서 차례를 양보**합니다. 총 숙제가 줄지는 않습니다. 양보가 많으면 오히려 전체 시간이 늘 수 있습니다. 그래도 다른 일을 오래 기다리게 하지 않는 장점이 있습니다.

Worker thread는 같은 사무실의 옆자리입니다. JavaScript 계산을 다른 스레드에서 수행합니다. 일반 객체는 메시지로 보낼 때 복사됩니다. 별도로 SharedArrayBuffer를 만들면 그 버퍼만 함께 볼 수 있고, 이번에는 Atomics로 숫자를 바꿉니다. 공유할수록 순서와 경쟁 문제를 신경 써야 합니다. [Node 공식 Worker 설명](https://nodejs.org/api/worker_threads.html)을 확인하세요.

Child process는 다른 사무실입니다. PID가 다르고 일반 객체를 함께 쓰지 않습니다. 메신저처럼 결과를 주고받아야 합니다. 시작 시간·추가 메모리도 필요합니다. [Node 공식 자식 프로세스 설명](https://nodejs.org/api/child_process.html)을 참고하세요.

**동시성**은 여러 일의 진행 시간이 겹치는 것입니다. 한 사람이 숙제와 답변을 번갈아 할 수도 있습니다. **병렬성**은 여러 실행 자원이 실제로 같은 시간에 일을 하는 것입니다. CPU 코어·운영체제 스케줄에 영향을 받습니다. 이번 실험은 한 번에 계산 작업 하나만 보내므로 여러 코어의 처리량이 몇 배 늘어나는지 증명하지 않습니다.

## JSON에서 딱 네 군데 읽기

- result: 방식이 달라도 계산 답은 같아야 합니다.
- order: probe가 result보다 먼저면 계산 완료 전에 예약한 콜백이 실행됐습니다.
- elapsedMs: 결과를 받기까지의 시간. 새 스레드/프로세스를 만드는 비용도 포함합니다.
- probeDelayMs: 작은 콜백의 대기 시간. 실제 네트워크·영상 지연이 아닙니다.

다른 컴퓨터의 PID나 ms가 달라도 괜찮습니다. 빠른 PC에서 작은 계산은 너무 짧아 시간 차이가 거의 안 날 수 있습니다. 시간 숫자보다 ‘계산 답은 같은데 다른 일의 차례가 달라졌다’를 먼저 관찰하세요.

자식에서 종료 코드 7을 내도 부모는 다음 실험을 계속합니다. 그러나 스레드는 프로세스 자원을 함께 쓰므로, 네이티브 코드 충돌이나 메모리 고갈까지 모두 격리한다고 말할 수 없습니다. 다음 주에는 Nest의 시작점을 나누고, 3주에는 Redis 큐로 아직 처리하지 않은 일을 보관합니다.
