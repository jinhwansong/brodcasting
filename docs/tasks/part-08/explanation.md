# 첫 시도 뒤 읽는 해설

<details><summary>재생 부탁과 실제 재생</summary>

play()는 시작을 요청하는 함수입니다. 브라우저 정책이나 파일 문제로 실패할 수 있어 catch가 필요합니다. 화면의 ‘재생 중’은 playing 이벤트에서 바꿉니다. waiting 뒤 다시 playing이 오면 재생 중으로 돌아갑니다. 실제 파일 오류와 잠깐의 기다림을 나눠 안내해야 합니다.

</details>

<details><summary>이전 영상이 새 영상을 건드리지 않게 하기</summary>

source와 재시도 번호로 key를 정해 새 재생기를 만듭니다. 이전 재생기는 이벤트를 떼고 정지하고 src를 없앤 뒤 load로 자원을 해제합니다. 정리 후 늦게 끝난 Promise는 alive 확인에서 무시합니다. 이벤트 기록도 최근 8개만 남깁니다.

</details>

<details><summary>기본 조작을 먼저 쓰는 이유</summary>

native controls는 재생·정지·탐색·음량·자막 조작을 제공합니다. 직접 만든 버튼만으로 모두 대체하면 키보드와 보조 기술의 동작까지 새로 책임져야 합니다. 기본 조작도 브라우저별 실제 확인은 필요합니다. jsdom은 실제 미디어를 재생하지 않습니다.

</details>

독립 변경인 시청 위치 복원 답안은 제공하지 않습니다. 생성 영상의 파일 디코딩과 브라우저에서 실제 재생한 증거는 구분합니다.
