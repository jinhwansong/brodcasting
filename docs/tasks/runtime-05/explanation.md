# 쉬운 해설

트랜잭션은 여러 작업을 한 묶음으로 성공시키는 약속입니다. 순번만 올리고 알림 저장이 실패하면 빈 번호와 복구 문제가 생기므로 같이 되돌립니다. 같은 사용자 카운터를 잠그면 작은 번호가 늦게 저장되어 새 알림 조회에서 빠지는 일을 막을 수 있습니다.

DB와 Redis는 서로 다른 저장소라 한 번에 성공한다고 보장할 수 없습니다. 먼저 DB에 접수증을 남기고, 큐에 넣지 못했으면 나중에 다시 접수합니다. 이때 Worker는 알림이 이미 있는지 확인하므로 같은 일이 반복되어도 알림은 하나입니다.

화면도 계정과 요청 번호를 확인합니다. 이전 계정의 느린 응답이 도착해도 현재 계정 화면에 섞지 않습니다. 접수 결과를 모를 때는 새 번호를 만들지 않고 원래 번호와 내용으로 확인합니다.
