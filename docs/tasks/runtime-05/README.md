# 알림5주 — 내 알림함

알림을 보내겠다는 **접수증**과 화면에 도착한 **알림**을 나눕니다. 음식 주문을 접수했다고 배달이 끝난 것은 아닌 것과 같아요. DB의 사건은 접수증, Redis 큐는 할 일 목록, Worker는 그 일을 처리하는 별도 프로그램입니다.

## 시작 전 예상
Worker를 끈 채 알림을 접수하면 무엇이 남을까요? 같은 접수 번호로 두 번 보내면 알림은 몇 개여야 할까요? 같은 시각에 도착한 알림의 순서를 시간만으로 나눠도 될까요? 먼저 예상해 적으세요.

## 직접 만들기
1. `labs/runtime-05`에서 `npm ci`, `npm run check`를 실행합니다. Docker Desktop을 켜 두세요. 처음에는 TODO 때문에 실패합니다.
2. `src/inbox.ts`의 `deliver`를 만듭니다. 사건을 잠그고, 이미 배달했는지 확인하고, 사용자별 순번과 알림을 한 트랜잭션에 저장합니다. 하나라도 실패하면 모두 되돌립니다.
3. `list`를 만듭니다. 반드시 로그인한 userId로 범위를 좁히고 순번으로 이전/다음을 구분합니다. 21개를 읽어20개만 보여 주면 다음 페이지 유무를 알 수 있어요.
4. `npm run check`, `npm run typecheck`, `npm run build`로 확인합니다.
5. `node dev-lab.mjs`를 켜고 두 계정을 만드세요. 한 계정의 알림이 다른 계정에 보이지 않는지 확인하세요. Worker를 멈추고 접수한 뒤 다시 시작해 알림이 한 번만 도착하는지 봅니다. 주소와 명령은 터미널 안내를 따르세요.

## 설명3개
- 접수와 도착을 나눈 이유를 자기 말로 설명하세요.
- 알림 저장과 순번 증가를 함께 되돌려야 하는 이유를 설명하세요.
- 시간 대신 순번을 사용하는 이유를 같은 시각 알림 두 개로 설명하세요.
