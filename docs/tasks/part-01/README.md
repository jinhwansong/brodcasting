# 1단계 — 시청 화면과 사용자 상호작용

2주, 주당 6~8시간을 권장합니다. 목록과 상세가 같은 데이터를 공유하는 화면을 만들고, 상태·파생 값·DOM 참조·Effect의 수명을 구분하는 것이 목표입니다. 실제 영상 재생은 8단계에서 다룹니다.

## 시작 전에

0단계에서 검색·정렬·즐겨찾기·로딩 상태를 설명하고 독립 변경까지 해본 뒤 진행하세요. 이번 시작 코드에는 그 선수 기능의 구현이 제공됩니다. 0단계 제출물을 복사하거나 기본 실행 명령을 바꿀 필요가 없습니다. 참고 완성본 열람은 자신의 첫 구현과 검증 이후로 미루세요.

[제출 양식](submission.md)에 먼저 예상하세요.

1. 방송 A를 선택하고 검색으로 A를 목록에서 숨기면 상세와 포커스는 어디에 있어야 할까요?
2. 상세에서 즐겨찾기를 바꾸면 목록의 어떤 값이 바뀌어야 하나요? 같은 값을 두 상태에 저장하면 어떤 문제가 생길까요?
3. 메뉴를 세 번 열고 닫거나 방송을 바꾸면 이벤트 처리기와 타이머는 몇 개 남아야 할까요?

npm ci
npm run dev:part-01
npm run typecheck:part-01

## 구현 계약

### A. 목록·상세·하나의 상태

- App이 전체 방송, 검색·정렬·즐겨찾기 조건, 즐겨찾기 id 집합, 선택 id를 소유합니다. 선택 객체나 필터 결과를 별도 상태로 복사하지 않습니다.
- `getSelectedBroadcast(items, selectedId)`는 전체 원본 중 같은 id의 현재 객체를 반환합니다. 선택 없음·없는 id는 `undefined`입니다. 입력을 수정하지 않습니다.
- `BroadcastList`의 `onSelect(id, trigger)`에서 trigger는 누른 실제 버튼입니다. 상세 선택 시 해당 제목에 포커스를 줍니다. 즐겨찾기만 변경할 때 제목으로 포커스를 빼앗지 않습니다.
- 검색·정렬·즐겨찾기 조건 변경으로 선택한 방송이 목록에서 사라져도 **상세는 유지**합니다. 전체 원본과 표시 목록의 차이를 설명하세요.
- 상세 닫기는 원래 선택 버튼이 아직 문서에 있으면 그 버튼, 없으면 방송 검색 입력으로 포커스를 돌립니다. 검색·정렬 조건은 유지합니다.
- 목록과 상세의 즐겨찾기는 같은 id 집합을 읽고 같은 변경 함수를 사용합니다. 양쪽 표시가 즉시 일치해야 합니다.
- 다른 방송을 선택하면 상세가 바뀝니다. ‘다시 불러오기’나 오류 후 ‘다시 시도’는 선택을 해제하고 로딩 흐름을 다시 시작합니다.

### B. 목록 옵션 펼침 영역

- 초기에는 닫힘. 버튼의 `aria-expanded`와 `aria-controls`가 실제 영역의 표시·id와 일치해야 합니다.
- 내부에는 실제 체크박스와 초기화 버튼이 있습니다. `role="menu"`·`menuitem`을 붙이는 복잡한 메뉴 실습이 아닙니다. Tab으로 일반 컨트롤을 이동합니다.
- 즐겨찾기만 조건 변경은 기존 검색·정렬을 보존합니다. 조건 초기화는 세 조건을 기본값으로 돌립니다.
- Escape는 닫고 목록 옵션 버튼으로 포커스를 돌립니다. 바깥 포인터 클릭은 닫되 클릭한 요소의 포커스를 방해하지 않습니다. 다른 키는 닫지 않습니다.
- 메뉴가 닫히거나 컴포넌트가 사라질 때 문서 이벤트를 정리합니다. 반복 열기·닫기와 StrictMode에서도 처리기가 잔존하면 안 됩니다.

### C. 상세 체류 시간

- `useElapsedSeconds(broadcastId: string | null): number`. null이면 0이며 interval이 없습니다. 선택 시 0부터 1초마다 증가합니다.
- 방송 id가 바뀌면 이전 interval을 정리하고 0부터 다시 셉니다. 닫기와 언마운트에서도 정리합니다. Hook은 조건부 호출하지 않습니다.
- 이 값은 화면 체류를 설명하는 장난감 카운터입니다. 실제 시계·영상 시간·시청 통계가 아닙니다. 백그라운드 탭의 타이머 지연과 오차는 이번 구현에서 보정하지 않습니다.

### D. 반응형·키보드

- section·h1/h2/h3·label·실제 버튼을 유지합니다. 전체 행을 클릭 div로 대체하지 않습니다.
- 넓은 화면에서는 목록·상세 두 열, 좁은 화면에서는 한 열로 배치합니다. 긴 제목에도 가로 넘침이 없어야 합니다. 입력과 조작 버튼의 사용 가능한 크기, 눈에 보이는 포커스를 제공합니다.
- 실제 브라우저 검증은 사용자 요청으로 후속 작업입니다. [브라우저 체크리스트](browser-checklist.md)는 모두 미실행이며, jsdom 성공을 시각·보조기술 검증으로 기록하지 않습니다.

## 설명 질문 3개

1. 검색어 변경 → 표시 목록, 상세 즐겨찾기 변경 → 목록 표시의 흐름을 파일·함수·props로 따라가세요. 어떤 값이 state이고 어떤 값이 파생 값이며 왜 그렇게 나누었나요?
2. 선택한 방송을 검색으로 숨긴 뒤 닫는 순서에서 포커스를 어디로 옮기나요? state와 ref의 역할, 제목 포커스 Effect의 의존성을 설명하세요.
3. 메뉴 반복 열기·닫기, 방송 전환, 상세 닫기, StrictMode 재실행에서 무엇을 등록하고 정리하나요? 정리를 지우면 재현할 수 있는 잘못된 동작을 하나씩 예상하세요.

## 해설을 가리고 할 독립 변경

즐겨찾기만 보기에서 선택한 방송의 즐겨찾기를 해제하면 기본 정책은 ‘목록에서만 사라지고 상세 유지’입니다. 이를 **‘상세도 닫기’로 바꾸세요**. 어떤 조작에서만 닫을지 먼저 명세하고, 원래 버튼이 사라지는 경우의 포커스 목적지도 정하세요. 일반 검색으로 숨길 때의 기존 계약은 보존합니다. 초기 선택·해제, 다른 항목 해제, 조건이 꺼진 경우를 포함해 자신의 검증을 추가하세요. 기존 기본 계약을 의도적으로 바꾼 테스트는 변경 전후 이유를 기록하고 나머지 회귀를 확인합니다. 이 변경의 완성 코드는 제공하지 않습니다.
