# F3 — 배포 파일과 CSP

브라우저에 보낸 파일은 사용자가 읽을 수 있어요. 비밀값을 프론트에 넣고 Git에서만 숨겨도 브라우저에 보내졌다면 숨겨진 것이 아닙니다.

## 먼저 예상하기

실행 전에 무엇이 성공하고 무엇이 거부돼야 하는지 적으세요. policy.mjs의 policyHeaders 함수를 직접 구현합니다. 참고 완성본은 첫 구현 뒤에 비교하세요.

## 실습 순서

1. npm ci 후 npm run experiment를 실행합니다. 실제 비밀값 대신 COURSE_PUBLIC_SENTINEL이라는 가짜 글자만 씁니다. Vite 빌드에서 노출된 뒤 제거되는지 확인합니다.
2. npm run check를 실행합니다. Report-Only와 차단 정책은 실제 HTTP 응답 헤더 이름이 다릅니다. 제공된 정상 정책과 검사를 읽고 TODO를 구현합니다.
3. npm run build 후 npm run serve로 http://127.0.0.1:5201을 엽니다. API 확인·WebSocket 연결·테스트 영상과 자막을 확인합니다.
4. PowerShell에서는 $env:PORT="5200"; $env:CSP_MODE="report"; node serve.mjs로 관찰 모드를 별도 터미널에서 실행합니다. 인라인 스크립트 시험은 작은 화면 표식만 바꾸는 로컬 실험입니다.
5. 관찰 모드에서는 표식이 실행되고 report가, 차단 모드에서는 실행 안 됨과 enforce가 표시돼야 합니다. 정상 API·영상·소켓을 망가뜨리지 않았는지도 확인합니다.
6. npm audit --json으로 잠금 파일의 실제 의존성을 확인합니다. 결과를 패키지 사용 위치·공식 공지·수정 선택·회귀 검사와 연결하세요. 강제 일괄 업데이트는 하지 않습니다.

## 설명3개

1. Git 제외와 브라우저 번들 제외는 어떤 차이가 있나요?
2. Report-Only 관찰과 실제 차단의 증거를 구분하세요.
3. 스캐너 결과 하나가 실제 코드에 미치는 영향을 설명하세요.
