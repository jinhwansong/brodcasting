# 11단계 — 새 부탁을 읽고, 고치고, 설명하기 (1주)

기능을 외워서 따라 만드는 것과 처음 보는 부탁을 해결하는 것은 다릅니다. 이번에는 **요구사항을 읽고 → 영향 범위를 적고 → 코드를 고치고 → 증거로 설명**합니다. [쉬운 설명](lesson.md)을 먼저 읽으세요.

## 이번에 받은 새 요구사항

> 채팅방마다 최근 글을 100개·500개·1,000개 중 골라 보관하고 싶습니다. 멈춘 상태에서 수를 줄여도 즉시 반영해야 합니다. 수를 늘려도 이미 버린 옛 글을 지어내면 안 됩니다. 방별 선택은 따로 기억하고, 숫자를 바꿨다고 60초 실험 시간이 다시 시작되면 안 됩니다. 입력 중인 글과 읽던 흐름도 지켜 주세요.

이것은 7단계 실험실에 적용하는 작은 변경입니다. 실제 서버의 DB 보관 정책을 바꾸는 과제가 아닙니다. 이번에는 방 이동 시 재생·목록을 초기화하며 **방별 선택값만** 이 탭에서 기억합니다. 새로고침하면 선택도 초기화합니다.

## 코드 전에 30분

[영향 분석 양식](impact.md)에 먼저 적습니다.

1. ‘즉시 반영’, ‘방별’, ‘버린 글을 복원하지 않기’를 내 말로 풀어 씁니다.
2. 선택 입력·배열 보관·반영 타이머·스크롤·공개 검사 중 바뀔 곳과 그대로 둘 곳을 찾습니다.
3. 먼저 확인할 실패 상황 세 가지를 고릅니다. 예상부터 적고 실행합니다.

## 실행과 작업 위치

루트의 Node 준비·`npm ci` 뒤 실행합니다.

```sh
npm run dev:part-11
```

http://127.0.0.1:5191 에서 ‘11단계 · 새 요구사항 적용’ 화면을 봅니다. 서버·DB는 필요 없습니다. 시작 코드는 기존 7단계 선수 구현과 새 UI 연결을 제공합니다. 새 핵심은 labs/part-11/src/retention.ts에 남겼습니다.

| 파일 | 역할과 점검할 이유 |
| --- | --- |
| retention.ts | 내 과제 A: 선택 문자열 검증, B: 최근 글 상한 적용 |
| App.tsx | 제공: 방별 선택값 저장·UI 연결. 왜 방 밖에 상태가 있는지 설명 |
| useReplay.ts | 제공: 선택 변경 즉시 자르기·타이머의 최신 상한 읽기. 왜 타이머를 다시 만들지 않는지 설명 |
| Timeline.tsx, window.ts | 제공: 읽던 위치·가상화. 줄어든 목록에서도 범위가 안전한지 확인 |
| checks/part-11/ | 단위 검사와 실제 React 변경 흐름 검사 |

A는 정확히 '100', '500', '1000'만 허용하고 나머지는 null로 거부합니다. B는 원본을 바꾸지 않는 새 배열을 반환합니다. 자료가 적다면 그대로 남기되 배열은 새로 만듭니다. 완성본과 [해설](explanation.md)은 첫 시도 뒤에만 확인합니다.

## 직접 확인할 순서

1. 낮은 속도 재생부터 확인하고 500개/초로 올립니다. 일정량이 쌓이면 중지합니다.
2. 보관을 1,000→100으로 줄입니다. 다시 재생하지 않아도 100개여야 합니다. 1,000으로 늘려도 100개 그대로여야 합니다.
3. 방 1은 100개, 방 2는 500개를 고릅니다. 오가며 선택은 기억하되 목록과 재생은 초기화되는지 봅니다.
4. 재생 후 59초에 선택을 바꿔도 60초에 멈춰야 합니다. 시간을 다시 주면 요구사항 위반입니다.
5. 입력칸에 글을 쓰고 위쪽을 읽던 중 상한을 줄입니다. 입력은 남고, 읽던 글이 보관 밖이면 안내가 있어야 합니다.

```sh
npm run typecheck:part-11
npm run build:part-11
npm run check:part-11
npm run preview:part-11
```

빌드 미리보기는 http://127.0.0.1:4291 입니다. 실제 브라우저 확인은 [후속 양식](browser-checklist.md)에 남깁니다. 자동 검사가 학습자의 독립 변경·설명을 대신하지 않습니다.

## 설명 질문 3개

1. 요구 문장 하나가 어느 상태·함수·검사를 바꾸게 했는지 연결하세요.
2. 선택 변경으로 타이머를 다시 만들면 왜 60초 규칙이 깨질 수 있나요?
3. 다른 해결 방법 하나와 지금 선택한 방법의 한계를 설명하세요.

## 완성본을 가리고 할 독립 변경

**방을 바꿔도 각 방의 최근 글과 읽던 위치를 유지하되, 두 방을 합쳐 최대 1,000개만 보관**하도록 바꾸세요. 어느 방의 옛 글부터 버릴지 먼저 정책을 적습니다. 타이머는 선택한 방에만 있어야 하고, 버린 글이 다시 나타나면 안 됩니다. 이 독립 과제의 구현 답은 제공하지 않습니다.

## 지원 자료 3개 만들기

[사례 양식](cases.md)에 직접 수행한 사례 3개를 씁니다. 문제·증거·선택·본인 기여·결과·한계를 넣습니다. 제작자가 실행한 검증을 내 경험으로 적지 않습니다. 회사 성과와 개인 로컬 실험도 나눕니다. [제작자 예시](producer-examples.md)는 글의 형식만 참고하고 본인 성과로 복사하지 않습니다.
