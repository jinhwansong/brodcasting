# 제작자 사례 예시 — 학습자 성과가 아닙니다

아래는 AI 제작자가 만든 교재의 사례입니다. 학습자는 아직 0단계·미시작입니다. 직접 재현·판단·변경하기 전에는 자신의 경험으로 적지 않습니다. 숫자는 각 검증 문서의 실행 범위 안에서만 사용합니다.

## 예시 1 — 응답을 못 받았다고 새 글로 보내면 중복될 수 있다

- 문제: DB 저장 직후 연결이 끊겨 확인 응답을 잃으면 화면은 저장 여부를 모를 수 있습니다.
- 선택: 같은 계정·방·발송 ID로 재시도해 기존 저장 결과를 확인합니다. 저장 순서와 표시 중복도 별도로 다룹니다.
- 제작자 기여: AI가 참고 구현·테스트·교재를 작성하고 실제 DB/소켓 실패를 재현했습니다.
- 증거: [6단계 검증](../../verification/part-06.md).
- 한계: 영구 outbox·다중 서버·실제 브라우저는 검증 범위가 아닙니다. 학습자 독립 변경은 미실행입니다.

## 예시 2 — 보관 개수와 화면에 그린 개수는 다르다

- 문제: 보관한 모든 글을 매번 그리면 화면 작업이 늘어납니다. 가상화만으로 배열 보관량까지 줄어들지는 않습니다.
- 선택: 데이터 보관 1,000개와 화면 범위를 따로 제한하고, 묶음 갱신·읽던 위치·타이머 정리를 검사합니다.
- 제작자 기여: AI가 실험실·공개 검사·기기 측정 양식을 작성했습니다.
- 증거: [7단계 검증](../../verification/part-07.md).
- 한계: 자동 DOM 검사와 실제 기기에서 빨라졌다는 측정은 다릅니다. 실제 브라우저 수치는 미작성입니다.

## 예시 3 — 백업 파일과 실제 복원은 다르다

- 문제: 파일을 만들기만 하고 복원·권한을 확인하지 않으면 고장 때 쓸 수 있는지 모릅니다.
- 선택: 소유한 로컬 테스트 DB를 새 이름의 DB로 복원하고 실제 HTTPS/WSS 계정·이력을 확인합니다. 실패 이미지 뒤 정상 이미지로 되돌립니다.
- 제작자 기여: AI가 로컬 환경과 검사기를 작성했습니다.
- 증거: [10단계 검증](../../verification/part-10.md). 실제 성공 범위는 해당 실행 기록을 따릅니다.
- 한계: 공개 운영·진짜 이용자·실제 브라우저·DB 형식 변경의 자동 롤백은 포함하지 않습니다.
