# 첫 실험 뒤 읽는 해설

<details><summary>표본을 정렬해서 보는 이유</summary>

원시 측정은 발생 순서로 남깁니다. 요약할 때만 복사해 정렬합니다. nearest-rank는 ceil(n×p)번째 값을 고릅니다. 빈 표본은 null이고 잘못된 표본은 오류입니다. 실패 응답을 빼고 성공한 응답만 보는 값과 모든 응답 값도 구분해야 합니다.

</details>

<details><summary>네 명씩 처리하는 경계</summary>

배열을 폭만큼 잘라 각 묶음의 모든 결과를 기다립니다. 실패가 있으면 현재 묶음이 끝난 뒤 실패를 반환하고 다음 묶음을 시작하지 않습니다. Gateway는 기존 세션·회원권·방 버전을 그대로 확인합니다. 동시 처리로 도착 순서가 달라져도 저장 순서와 복구 cursor는 6단계 DB 계약을 따릅니다.

</details>

<details><summary>한 실험의 한계</summary>

부하를 주는 쪽과 서버는 서로 다른 프로세스이지만 같은 컴퓨터입니다. DB probe는 저장 SQL의 시간을 직접 보여 주지 않습니다. 외부 네트워크·진짜 브라우저·많은 시청자·긴 시간의 결과는 없습니다. 이 한계를 적어야 다음에 무엇을 측정할지 결정할 수 있습니다.

</details>

독립 변경의 연속 오류 구간 정책 답은 싣지 않습니다.
