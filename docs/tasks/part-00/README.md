# 0단계 — 현재 실력 확인

목표는 멋진 완성 앱이 아니라, 입력부터 화면까지 스스로 설명하고 작은 변경을 해내는 것입니다. 1주, 총 6~8시간을 권장하되 막히는 부분을 진단하는 시간이므로 속도를 점수로 삼지 않습니다.

## 먼저: 코드 없이 20분

[제출 양식](submission.md)에 다음을 먼저 적으세요.

1. 검색어·정렬·즐겨찾기를 바꾸면 데이터가 어떤 순서로 흘러갈지 5~10줄로 예상합니다.
2. 배열을 정렬할 때 원본 참조가 바뀌는지, Set에 추가만 하면 React 화면이 바뀌는지 예상합니다.
3. 아래 출력 순서를 **실행 전에** 적고 이유를 한 문장씩 씁니다.

```js
console.log('A');
setTimeout(() => console.log('B'), 0);
Promise.resolve().then(() => console.log('C'));
console.log('D');
```

예측 후 브라우저 콘솔 또는 Node에서 실행하고 차이를 기록하세요. 답은 [해설](explanation.md)의 접힌 영역에 있습니다.

## 실행과 수정 위치

저장소 루트에서 `npm ci`, `npm run dev`. 작업은 `labs/part-00/src/`에서만 시작합니다.

| 파일 | 직접 채울 부분 |
| --- | --- |
| `domain.ts` | A: 조건을 조합한 목록 조회, B: 원본을 바꾸지 않는 즐겨찾기 |
| `App.tsx` | C: 로딩·성공·실패 상태와 재시도 연결 |
| `types.ts`, `fixtures.ts`, `loadBroadcasts.ts` | 제공되는 계약·가짜 데이터·모의 로더. 먼저 읽되 임의로 계약을 바꾸지 않기 |
| `BroadcastView.tsx`, `styles.css` | 제공 UI 골격. 기본 흐름이 되기 전 디자인 확장은 하지 않기 |

## 요구사항과 예시

- 방송은 고정된 가짜 데이터 6개입니다. 외부 API, 로그인, 영상 재생, 저장소·서버가 필요하지 않습니다.
- 검색어는 앞뒤 공백을 제거하고 제목 **또는** 진행자 이름에 대소문자 무시 부분 일치로 적용합니다.
- 공백 검색어는 전체 목록입니다. ` rEaCt `는 ‘새벽 React 작업실’, ‘React 상태 실험’을 찾고 시청자 순이면 후자가 먼저입니다.
- `viewers-desc`는 시청자 내림차순, `title-asc`는 한국어 로케일 제목 오름차순입니다. 같으면 id 오름차순입니다.
- 즐겨찾기 전용 조건은 검색과 함께 적용됩니다. 즐겨찾기를 해제하면 즉시 목록에서도 사라집니다.
- 조회와 토글은 원본 배열·방송 객체·Set을 바꾸지 않습니다. 새 탭·새로고침 뒤 저장은 이번 요구사항이 아닙니다.
- 검색·정렬·즐겨찾기 상태를 바꿔도 서로의 조건을 잃지 않습니다. 조회 결과는 원본 상태로부터 계산합니다.
- 처음과 재로딩 중에는 로딩 안내, 실제 빈 데이터에는 ‘등록된 방송이 없습니다.’, 조건에 맞는 결과가 없으면 ‘검색 조건에 맞는 방송이 없습니다.’를 표시합니다.
- 실험 데이터에서 오류를 선택해 불러오면 오류 안내와 ‘다시 시도’가 나옵니다. 다시 시도는 정상 데이터를 불러옵니다.
- 서버 작업 취소를 구현하는 실습은 아닙니다. 화면을 떠난 뒤 늦은 Promise 결과로 상태를 갱신하지 않는 이유를 설명하세요.

## 설명 질문 3개

1. 검색어 한 글자가 바뀐 순간부터 표시되는 방송이 바뀔 때까지, 함수·상태·컴포넌트를 코드 위치로 따라가세요.
2. `sort()`와 Set 직접 변경이 어떤 문제를 만들 수 있나요? 현재 코드가 입력을 바꾸지 않는다는 증거는 무엇인가요?
3. 오류 후 재시도에서 바뀌는 상태를 순서대로 설명하고, Promise가 끝나는 시점과 화면 표시가 같은 순간인지 설명하세요.

## 해설을 가리고 풀 변경 과제

‘최소 시청자 수’ 필터를 하나 추가하세요. 기본값은 0이며 검색·정렬·즐겨찾기와 함께 적용되어야 합니다. 원본 목록은 그대로 남아야 합니다. 입력값 0, 경계값, 결과 없음의 검증을 직접 추가하세요. 이 확장은 공개 기본 테스트에 포함되지 않으므로 테스트 통과를 변경 과제 완료로 대신할 수 없습니다.
