# 쉬운 설명 — 입구·작업실·보관실

## 입구 하나만 열어 둡니다

가게 손님이 주방이나 창고로 바로 들어가면 관리하기 어렵습니다. 웹 서비스에서도 브라우저는 **프록시**라는 입구로 들어오고, 프록시가 API 작업실로 요청을 옮깁니다. DB 보관실은 API가 정해진 권한으로 사용합니다. API와 DB에 바깥 포트를 열지 않는 이유입니다.

**HTTPS**는 브라우저와 입구 사이의 내용을 암호화하는 통신입니다. **WSS**는 같은 보호를 받는 WebSocket 연결입니다. 암호화했다고 누구나 모든 방에 들어갈 수 있는 것은 아닙니다. 로그인과 방 회원권 확인은 API의 별도 일입니다.

**인증서**는 연결한 입구가 누구인지 확인하는 데 쓰는 자료입니다. 이번에는 내 컴퓨터용 인증서를 직접 만듭니다. 이것을 실제 회사 사이트의 신뢰할 수 있는 인증서로 간주하면 안 됩니다.

## 입구의 말도 아무나 믿지 않습니다

프록시는 API에 ‘이 요청은 HTTPS로 들어왔다’고 전합니다. 아무 요청이나 그 말을 붙일 수 있게 하면 거짓말이 섞입니다. 그래서 API는 정해 놓은 프록시 IP만 믿고, 프록시는 손님이 보낸 전달용 헤더를 자기 값으로 덮어씁니다.

## 불은 켜졌는데 주문은 못 받을 수도 있어요

API 프로세스가 켜져 있어도 DB가 꺼져 있으면 주문을 저장할 수 없습니다. **live**는 불이 켜졌는지, **ready**는 지금 주문을 처리할 수 있는지에 가깝습니다. 둘을 나누면 어떤 고장인지 더 쉽게 알 수 있습니다.

**로그**는 문제가 났을 때 보는 작업 기록입니다. 하지만 비밀번호나 쿠키를 적으면 기록이 새는 것만으로 계정이 위험해질 수 있습니다. 필요한 오류 종류와 요청 번호만 적고, 그 번호로 화면의 오류와 연결합니다.

## 사진을 찍는 것과 다시 짓는 것은 달라요

**백업**은 보관한 내용을 다른 형태로 담아 두는 일입니다. **복원**은 그 내용을 새 DB에 다시 넣어 실제로 읽을 수 있는지 확인하는 일입니다. 파일 하나 생겼다고 복원이 된 것은 아닙니다.

**롤백**은 잘못 바꾼 프로그램을 이전 정상 프로그램으로 되돌리는 일입니다. 프로그램과 DB는 별개입니다. 새 프로그램이 DB 내용을 지웠다면 옛 프로그램만 다시 켠다고 데이터가 돌아오지 않습니다. 그래서 이번 실습은 원본을 덮지 않고 새 DB에 복원하며, 고장 이미지도 데이터 형식은 바꾸지 않게 만듭니다.
