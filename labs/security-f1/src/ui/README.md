# 온에어 라운지 공통 UI

디자인 시스템은 **여러 화면이 같이 쓰는 모양과 조작 규칙**입니다. 버튼을 만들 때마다 색과 크기를 새로 정하지 않도록 준비한 부품이에요.

## 어디를 고치면 될까요?

| 바꾸려는 것 | 파일 | 예시 |
| --- | --- | --- |
| 색·글자 크기·간격 | [tokens.css](tokens.css) | 민트색, PC 본문16px·모바일14px, 기본 간격8px |
| 버튼·입력창·상태의 모양 | [system.css](system.css) | 선택·포커스·오류·비활성 |
| 조작과 접근성 | [components.tsx](components.tsx) | 처리 중 중복 클릭 차단, 입력 이름 연결 |

토큰은 **이름 붙인 값**입니다. `--color-accent`는 주요 동작에 쓰는 색이에요. 화면마다 민트색 숫자를 적는 대신 이 이름을 사용합니다. 색을 바꾸면 같은 토큰을 쓰는 곳이 함께 바뀝니다.

화면의 배치는 `../styles.css`, 디자인 가이드 배치는 `../design-system.css`에 있습니다. 방송 카드는 `../BroadcastCard.tsx`를 목록과 가이드에서 같이 사용합니다. 로그인·채팅 권한과 서버 저장은 각각의 기능 코드가 담당합니다.

## 부품 사용하기

```tsx
import {Button, TextField, InlineNotice} from './ui/components';

<Button variant="primary" busy={saving} onClick={save}>공지 저장</Button>
<Button variant="ghost" onClick={reload}>다시 조회</Button>
<TextField label="방송 제목" value={title} onChange={e => setTitle(e.target.value)}
  hint="60자까지 입력할 수 있어요." error={error ?? undefined}/>
<InlineNotice tone="error">연결을 확인하고 다시 조회하세요.</InlineNotice>
```

- 중요한 행동은 `primary`, 보조 행동은 기본값, 덜 강조할 행동은 `ghost`, 종료처럼 주의할 행동은 `danger`를 씁니다.
- `Button`의 기본 타입은 `button`입니다. **폼을 제출할 버튼에는 `type="submit"`을 꼭 씁니다.** 조회·전환 버튼이 실수로 폼을 제출하지 않게 한 규칙이에요.
- 저장 중에는 `busy`를 사용합니다. 버튼 이름은 그대로 남고 중복 클릭을 막습니다. 서버의 중복 방지 검사는 따로 유지해야 합니다.
- `IconButton`에는 `label="창 닫기"`처럼 이름을 넣습니다. 그림만 보는 사람이 아니어도 무슨 버튼인지 알 수 있어야 해요.
- 입력은 `TextField` 또는 `TextAreaField`를 씁니다. 이름·도움말·오류가 입력창과 연결됩니다. 비밀번호·최대 길이 같은 기능별 설정도 함께 넘겨 주세요.
- `Badge`는 짧은 상태, `InlineNotice`는 안내, `EmptyState`는 빈 목록에 씁니다. 색과 함께 글도 표시합니다.
- 대화상자는 브라우저의 `<dialog>`에 `ui-dialog`를 붙여 사용합니다. `showModal()`로 열고 `close()`로 닫습니다. Escape와 원래 버튼으로의 초점 복귀를 직접 확인하세요.

## 꼭 지킬 화면 규칙

- 어두운 바탕, 민트색 주요 동작, 분명한 제목과 읽기 쉬운 설명을 사용합니다. 실제 LIVE와 샘플 방송을 같은 상태로 표시하지 않습니다.
- 제목은20px 이상, 본문은PC16px·모바일14px, 배지는PC12~14px·모바일12px입니다. 목록 프로필은PC32px·모바일28px, 제목과 간격은8px입니다.
- 클릭할 때 겹친 테두리를 만들지 않습니다. 키보드 초점은 기존 테두리 자리에 한 줄로 표시합니다.
- 설명 글자는 최소12px입니다. 기본 버튼 높이는40px, 작은 버튼은36px, 휴대폰에서는44px입니다.
- 글과 버튼은 화면 폭이 줄면 줄바꿈합니다. 휴대폰 시청 화면은 영상→방송 정보→채팅→공지 순서입니다.
- CSS 파일의 첫 선언은 `@layer reset, tokens, app, components;`입니다. 기본값→토큰→화면 배치→공통 부품 순서를 유지해야 메뉴 선택과 입력 테두리가 사라지지 않습니다.
- 색은 토큰에 추가하고 사용합니다. 기능 화면에 새 색을 바로 적기 전에 기존 의미 색을 먼저 살펴보세요. 썸네일 그림과 영상 속 색은 별개입니다.
- 예제 입력도 일반 글자로 표시합니다. 입력한 HTML을 실행하는 코드를 넣지 않습니다.

## 직접 해볼 작은 실습

1. 실행 중인 사이트의 ‘디자인 가이드’를 열거나 주소 끝에 `#/design-system`을 붙입니다.
2. 예제 팔로우를 누릅니다. 아래 예제 방송 카드도 같은 팔로우 상태가 되는지 확인합니다.
3. `tokens.css`의 `--color-accent` 값을 잠깐 바꿉니다. 가이드와 실제 화면의 주요 버튼·선택 표시가 같이 바뀌는지 봅니다. 확인 후 원래 값으로 돌립니다.
4. 키보드의 Tab으로 이동하고 예제 대화상자를 엽니다. Escape로 닫았을 때 열기 버튼으로 초점이 돌아오는지 봅니다.
5. 화면을 휴대폰 폭으로 줄입니다. 입력과 버튼이 밖으로 튀어나오거나 가로 스크롤이 생기지 않는지 확인합니다.

생각해 보기: 색 한곳을 바꾸면 왜 여러 화면이 바뀔까요? 처리 중 버튼을 막아도 서버 검사가 필요한 이유는 뭘까요? 오류를 빨간색만으로 알리면 누가 놓칠 수 있을까요?

독립 WebRTC 교재는 이 부품을 자기 폴더 안에 복사해 제공합니다. 저장소 밖으로 가져가도 실행되도록 한 구조입니다. 원본은 `apps/broadcast/client/src/ui`이고 제공 UI 변경 시 양쪽 교재 복사본도 맞춥니다. 사이트 루트의 `npm run check:broadcast:design`은 이 일치 여부도 검사합니다. 학습자의 RTC TODO와 학습 통과 상태는 별개입니다.
